1. About CHA

CHA is a private application for conversations with one or more AI characters. It lets you choose who you speak as, choose who answers, organize conversations into forums, and keep useful sessions.

On a compatible Mac, CHA installs in the Applications folder and opens in its own window like any other application. Chrome, Safari, and other web browsers are not needed. CHA keeps its settings and conversations on the Mac and contacts the selected AI provider when a character prepares a reply.

CHA is intended for personal use. It does not replace professional medical, legal, financial, or emergency advice.

2. Install and start CHA on macOS

The standalone edition of CHA is a normal Mac application. Installation requires no Terminal commands and everyday use requires no web browser.

Before you begin

You need:

  • A Mac with Apple silicon, such as an M1, M2, M3, M4, or later chip. This edition does not run on an Intel Mac.
  • A copy of CHA built for the macOS version on that Mac. A build made for a newer macOS release cannot run on an older release.
  • An internet connection for AI-generated replies.
  • Either a ChatGPT account that can use the configured model, or an API key for the model provider you intend to use. Treat API keys like passwords: do not share them or include them in messages or downloaded conversations.

Install the application

  1. Obtain CHA-macos-<version>.tar.gz or CHA.app from a source you trust.
  2. If you received a .tar.gz file, double-click it in Finder. Finder extracts CHA.app, the archive's only item.
  3. Open a second Finder window and select Applications.
  4. Drag CHA.app into the Applications folder.
  5. Open Applications and double-click CHA. Do not open the application before extracting it and do not move or edit files inside CHA.app.

If macOS blocks the first launch

Because this personal-use application does not come from the Mac App Store, macOS may say that Apple cannot check it or that its developer cannot be verified. Continue only if you trust the person or place from which you received this exact copy.

  1. Try to open CHA once, then dismiss the macOS warning.
  2. Choose Apple menu > System Settings, then select Privacy & Security in the sidebar.
  3. Scroll to the Security area and select Open Anyway beside the message about CHA.
  4. Enter the Mac login password if asked, confirm the choice, and select Open in the final warning.

Do not override a warning that says CHA will damage the Mac, and do not continue if the copy came from an unexpected or untrusted source. Obtain a fresh copy instead. For more context, see Apple's guidance for opening applications safely.

Complete the first launch

  1. Wait while CHA creates the Default vault. The main window opens at the Welcome session, with the title CHA: Default.
  2. Open Settings and select OpenAI.
  3. Select Connect ChatGPT and complete the sign-in.

The Default vault starts with the built-in Assistant configured to use the connected ChatGPT account. You can instead add a model API key and provider under Settings. CHA remembers its settings, credentials, and saved conversations on that Mac.

The Welcome session is temporary. It is useful for a quick conversation, but it disappears when CHA quits. Create a normal session in a forum when you want the conversation to be saved.

Send your first message

  1. Click the message box at the bottom of the chat.
  2. Type your message.
  3. Press Ctrl+Enter, or select the Send button.

Pressing Enter by itself adds a new line. This makes it easy to write a message with several paragraphs before sending it.

Make the message box larger

Drag the divider above the message box upward or downward. The box can use up to 80% of the chat height. When the divider has keyboard focus, use the Up and Down arrow keys to resize it. Press Home or double-click the divider to return to the automatic size.

Open and quit CHA

  • To open CHA later, double-click it in Applications. You can also drag CHA from Applications to the Dock for convenient access.
  • To quit, choose CHA > Quit CHA, press Command+Q, or close CHA's only window.

If the selected vault is protected, CHA asks for its password before the window opens. A wrong password returns to the prompt. Choosing Quit leaves the vault closed.

Change model credentials

Open Settings → API Keys to add, rename, replace, or remove an API key. Open Settings → OpenAI to connect or disconnect ChatGPT. Saved API-key changes are available to providers immediately and apply only to the active vault.

Install an updated version

  1. Quit CHA completely.
  2. Extract the new CHA.app if it arrived in a .tar.gz file.
  3. Drag the new copy into Applications.
  4. Select Replace when Finder asks what to do.
  5. Open CHA normally. Existing settings and saved conversations remain.

Copy CHA to another Mac

Copy the .tar.gz file or CHA.app to the other Mac, place CHA in that Mac's Applications folder, and follow the first-launch steps above. The application can be copied, but credentials, vault databases, and saved conversations do not travel with it. The other Mac starts with its own Default vault.

3. The four main ideas

How CHA organizes a conversation
Item What it means Example
Persona The identity and background you use when speaking. You, a guest, or a role created for a particular kind of discussion.
Character The AI counterpart that replies, together with its instructions and provider settings. A general assistant, tutor, editor, or historical voice.
Forum A group of characters and the default persona used with them. A study group or a collection of advisers.
Session One saved conversation inside a forum. “Planning the autumn trip.”

A forum provides the setting. A persona says who is asking. A character says who answers. A session contains the actual conversation.

4. Finding your way around

The sidebar contains four main areas:

  • Personas shows the available speaking identities and their descriptions. Opening a persona here does not change your current persona.
  • Characters shows the available AI characters. Select one to read its description or, when allowed, change its settings.
  • Forums shows groups of characters. Open a forum to see its members, active persona, and saved sessions.
  • Recent gives quick access to recently used sessions.

Choose a persona when creating a forum. To change it later, open the forum, select its name above the session list, choose Members, select a persona, and save. The same screen adds or removes forum characters.

On a small screen, open the sidebar when you need it and close it to give the conversation more room.

Select the Settings gear at the bottom of the sidebar to manage vaults, the OpenAI connection, providers, character styles, and saved API keys. The vault selector beside Settings changes the active vault for the whole application.

5. Creating and managing sessions

Create a saved session

  1. Open Forums in the sidebar.
  2. Select the forum you want to use.
  3. Select New session.
  4. Enter a title when requested, then begin the conversation.

Open an earlier session

Select a session under Recent, or open its forum and choose it from the session list. Sessions in a forum are shown with the most recently used items first.

Rename, download, or delete

Open the action menu beside a session in the Recent list. Choose:

  • Rename to change the displayed title.
  • Download to save a Markdown copy.
  • Delete to remove the session from CHA.

A deleted session can no longer be opened in CHA. Download it first if you may need a readable copy later.

6. Having a conversation

See who is speaking

The information above the message box shows the forum, the persona in the From position, and the character in the To position. Check this line before sending if the forum has several members.

Choose one character for a message

Start a message with @Name to address a particular character: 

@Seneca How should I think about this setback?

CHA accepts an unambiguous full name, identifier, or partial name without regard to letter case. To start ordinary text with a literal at sign, type two at signs: @@example becomes @example.

Ask several characters

Choose All characters in the target menu to ask every forum member, or use /mcast to name several members: 

/mcast @Seneca @Epictetus What matters most here?

CHA shows the question once. A horizontal line separates each reply, so it remains clear where one answer ends and the next begins.

Save a Self-note without an AI reply

Start a message with @- to add it to the conversation without asking a character to respond: 

@- I made the decision this morning.

The note is saved in the conversation history. A character selected later can use it as context. Choose Self-notes in the target menu to keep saving messages without replies until you choose a character again.

Stop a reply

While CHA is generating an answer, the Send button changes to Stop. Select it to stop generation.

Use response controls

Small controls appear beside the timestamp below each AI response. When voice output is configured, the speaker button reads a completed response aloud. Select the crossed-out eye button to cover the conversation through that response. Select the red trash button to remove that response and the prompt that generated it. CHA asks for confirmation because this deletion is permanent and cannot be undone.

A second speaker button appears below the message box, immediately to the left of the Rus switch. Select it to prepare audio for every completed AI response in the current session and to prepare each later response when it finishes. CHA sends at most three of these preparation requests at once; a newly completed response goes ahead of older responses still waiting. The pressed button shows that automatic preparation remains enabled. Select it again to stop scheduling audio. Requests that have already started still finish and are cached.

Prepared and previously played response audio is kept in memory, up to 256 MiB, and replaying the same text with the same voice and settings does not call ElevenLabs again. The cache lasts only until the application or page is reloaded. Switching sessions turns automatic preparation off, but does not discard audio already cached. Voice-preview controls continue to create a fresh sample each time so they can be used for tuning.

Covered conversation remains visible, but later AI requests do not receive it as context. The eye button stays beside the response that established the boundary. Select it to restore the entire conversation to model context. Selecting the crossed-out eye beside an earlier covered response moves the boundary backward and exposes the responses after it.

Delete is offered only for a saved AI response that has its matching prompt; it does not apply to Self-notes, failed turns, or prompts stopped before an answer was recorded. Response controls are unavailable while CHA is generating a reply. A cover boundary is cleared when the session is reopened, or when deleting a turn leaves no covered conversation beneath it.

Write in any language

Enter text directly in the language you want to use. For a different alphabet or keyboard layout, use the normal input settings provided by your computer or phone.

7. Chat command

The multicast command begins with a slash and is entered in the same box as an ordinary message.

Session commands
Command Purpose Example or note
/mcast Send one prompt to more than one character. /mcast @One @Two Your question

8. Character settings

Open Characters, select a character, and then open Settings. The Settings option appears only for characters that can be changed. The built-in Assistant does not have this screen.

Character settings
Setting Meaning
Provider The AI provider and model used by this character.
Reasoning effort How much internal work the model may do before answering. Higher settings can take longer and may cost more.
Web search Whether the character may search the web, must search it, or must not search it.
Style The font treatment used to display this character's messages.

Saving character settings applies them to open conversations. If a reply is being generated, that unfinished reply will be lost.

9. Vault settings

A vault is one CHA database with its own workspace configuration and conversations. The selector beside Settings shows the active vault. Selecting another vault closes live sessions, opens that database, reloads the window at Welcome, and updates the window title. If the target is protected, enter its password in the dialog that appears.

Create a vault

  1. Open Settings and select Vaults.
  2. Select New vault and enter a display name.
  3. Under Initial database, choose New empty vault or copy an existing vault.
  4. To encrypt the database, select Protected vault, enter a password, and optionally use the eye button to check it.
  5. Select Create vault.

A new empty vault receives the active vault's characters, personas, forums, providers, styles, and saved model/R2 keys, but no saved sessions. Copying an existing vault copies its complete database, including saved sessions. A protected source can be copied only while it is active. Creating either kind adds it to the vault list but does not make it active. CHA chooses the database and working-folder paths from the display name.

Rename, protect, or remove a vault

Select a vault under Settings → Vaults. Use the pencil beside the page title to rename it. To encrypt an unprotected vault, select Protected vault, enter a password, and select Protect vault. Protection cannot be removed and the password cannot be changed in CHA. Keep it somewhere safe: CHA cannot recover a forgotten vault password.

Only an inactive vault can be removed, and CHA always keeps at least one vault. Removing a vault deletes its entry from CHA but keeps its database and folders on disk.

Download another vault from R2

When the active vault has R2 storage configured, select Download vault to see remote databases that are not already registered on this Mac. Select a name to download, validate, and add it as an inactive vault. This screen cannot add a protected remote vault because it does not ask for that vault's password.

10. Provider settings

A provider tells CHA which model endpoint to use and how to authenticate there. Select the Settings gear, then Providers. Choose an existing provider or select New provider and enter a name. A new provider can start with the default OpenAI settings or copy all settings from an existing provider, including its saved API-key choice.

Configure the provider

Provider settings
Setting What to enter
Model The exact model name accepted by the provider.
Base URL The provider's HTTP or HTTPS address, including a port or base path when required. Use HTTPS except for a local endpoint.
API format Responses or Chat completions, according to the endpoint.
Credentials A saved API key, OpenAI OAuth, or No credentials.

The provider's name appears as the page title. Select the pencil beside it to rename the provider without changing its identity.

Use a saved API key

  1. Open Settings and select API Keys.
  2. Select New API key, enter a recognizable name, paste the secret, and save it.
  3. Return to the provider and choose that name under Credentials.
  4. Select Save changes.

Only keys explicitly saved under API Keys appear in the Credentials list. Their secret values stay in the active vault database and are not returned to the browser. They are vault-specific and are included as plaintext when you export workspace configuration, so protect every export. CHA never reads model API keys from .env or process environment variables during normal use. If a provider refers to a key that no longer exists, that provider fails when tested or used.

Use OpenAI OAuth

Connect the ChatGPT account in Settings under OpenAI, then choose OpenAI OAuth under Credentials. This choice requires API format Responses and Base URL https://chatgpt.com/backend-api/codex. Choosing it records the intended authentication method; it does not connect an account by itself.

Test the provider

  1. Enter the provider settings you want to check.
  2. Select Test before saving.
  3. Wait for Provider responded successfully. or follow the reported error, then save the tested settings.

The test sends a small request using the settings currently in the form. It does not save them, include a conversation, create a session, or use web search. The test uses a 10-second timeout and may consume a small amount of provider usage.

Delete a provider

Select Delete provider and confirm. CHA will not delete a provider while a character still uses it; assign those characters to a different provider first.

11. Backing up and editing CHA data

The Database menu can export or import workspace configuration and can upload or download the complete database. These operations run inside the current CHA process; the application does not restart or launch a separate console program.

Find the active configuration files

The distribution archive contains only CHA.app. The application creates and uses ~/Library/Application Support/CHA. A fresh installation begins with the first five files and folders; the remaining credential files below appear only when used or migrated: 

~/Library/Application Support/CHA/app.toml
~/Library/Application Support/CHA/default.toml
~/Library/Application Support/CHA/default.sqlite3
~/Library/Application Support/CHA/mirror/
~/Library/Application Support/CHA/modify/
~/Library/Application Support/CHA/openai-auth.json   (after connecting OpenAI)
~/Library/Application Support/CHA/api-keys.json  (legacy migration only)
~/Library/Application Support/CHA/.env           (legacy migration only)

In Finder, choose Go > Go to Folder…, enter ~/Library/Application Support/CHA, and select Go. Additional vaults have their own generated TOML files and database paths. Use Settings rather than editing credential files by hand. Direct edits to app.toml or a vault TOML require restarting CHA.

Export, edit, and import workspace configuration

The optional modify setting in app.toml names the base directory used by both operations. CHA appends the active vault name. It may be relative to the application data directory: 

modify = "modify"

# The Personal vault uses the modify/Personal folder.

When this setting is absent, Import and Export are disabled. To edit workspace configuration:

  1. Wait for any current AI reply to finish.
  2. Choose Database > Export. CHA replaces an existing valid CHA workspace at the configured modify path, or creates the directory, and writes the current workspace configuration there.
  3. Edit the exported .toml or .md files.
  4. Choose Database > Import… and confirm the change.
  5. Wait for CHA to validate, store, and display the imported workspace.

Export permanently replaces an existing valid CHA workspace at the modify path. It refuses to replace an unrelated nonempty directory. Copy out any edits you still need before exporting again. Import replaces the complete workspace configuration and can remove sessions belonging to forums that are no longer configured. Exports are plaintext and include saved model and R2 keys, even when the vault database is password-protected.

Upload or download the complete database

Upload and Download use Cloudflare R2 through its S3-compatible API. Open Settings → API Keys → R2 storage and save the bucket URL, access-key ID, and secret key for the active vault. Upload and Download are enabled while that vault has all three values.

  • Database > Upload validates and uploads the current vault definition and database. The bucket receives two objects: the database filename and that filename followed by .toml.
  • Database > Download… asks for confirmation, saves the current database and vault definition beside themselves with .bac suffixes, downloads and validates both R2 objects, and refreshes CHA. Neither local file changes if validation fails.

R2 cannot replace the two remote objects atomically. Retry a failed upload before downloading. A database-only upload made by an older CHA version must be uploaded again by the current version before it can replace the active vault.

All four Database menu items are temporarily disabled while one database operation is running.

12. Downloading conversations

Use Download in a session's action menu to save a Markdown file. Markdown is plain text that remains readable in an ordinary text editor and is also supported by many note-taking applications.

The exported file is designed to be compact:

  • The session start time appears once near the beginning.
  • Each speaker is shown as a monospace badge followed by a middle dot.
  • Paragraphs within one reply stay close together.
  • A small gap separates one message from the next.
<!-- CHA session: An evening conversation -->
*Started September 03, 2026 at 17:47 PDT*

`Michael` · How can I make better use of the rest of today?

`Montaigne` · Begin by deciding whether you need rest or attention.  
Then choose one small act and do it completely.

13. Privacy and data

  • In the standalone Mac application, saved conversations and settings remain on that Mac. Replacing the application preserves them, while copying only the application to another Mac does not transfer them.
  • Prompts and the needed conversation history are sent to the configured AI provider when you request a reply.
  • If web search is enabled, the provider may use the web to prepare an answer. CHA stores the final answer, not the provider's search details.
  • Downloaded conversation files are separate copies. Protect or delete those files yourself when you no longer need them.
  • If you use Database Upload, the complete database is copied to the configured R2 bucket. An ordinary vault depends on that account's access controls; a protected vault remains encrypted in R2.
  • API and R2 keys are stored inside their vault database. OpenAI OAuth credentials are stored separately on the Mac. Treat all of them like passwords.

Anyone with access to your Mac account, unprotected database, workspace export, or downloaded conversation files may be able to read private data. Lock your Mac and do not share passwords or API keys. Vault protection encrypts the database, but not mirrors, exports, or downloaded conversations.

14. Troubleshooting

Common problems
Problem What to try
macOS says Apple cannot check CHA or cannot verify its developer. If the copy came from a trusted source, follow If macOS blocks the first launch. Otherwise, obtain a fresh copy from someone you trust.
CHA says that it could not open. Quit CHA, wait a few seconds, and open it again from Applications. If the problem remains, restart the Mac.
CHA says that this copy is incomplete. Delete only the application, obtain a fresh .tar.gz file, extract it again, and move the new CHA.app into Applications. Saved conversations remain on the Mac.
A reply fails immediately. Check the internet connection. Open Settings → Providers, select the provider, save any changes, and select Test. Check its saved API key under API Keys or reconnect under OpenAI if the provider uses OAuth.
A reply stops during generation. Check the internet connection, wait briefly, and send the message again. If the AI provider is unavailable, try again later.
The wrong character answers. Check the To value above the message box. Use the target menu to choose a default or begin one message with @Name.
The wrong persona is shown. Check the From value. Open the forum, select its name above the session list, choose Members, select the persona, and save.
Typing Enter sends nothing. This is expected. Enter adds a new line; use Ctrl+Enter or the Send button.
Import and Export are disabled. Add a modify base path to app.toml, then quit and reopen CHA. A first-run installation already has modify = "modify".
Upload and Download are disabled. Open Settings → API Keys → R2 storage and save a complete URL, access-key ID, and secret for the active vault.
CHA asks for a vault password. Enter the password chosen when the vault was created or protected. CHA does not store or recover it. A correct password still failing can mean the encrypted database is damaged; restore a known-good backup.
A protected vault cannot be downloaded from the Vaults screen. That screen cannot ask for a remote vault's password. Register or create the vault locally, then use the password-aware Database → Download operation for that active vault.
