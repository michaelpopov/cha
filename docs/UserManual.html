1. About CHA

CHA is a private browser application for conversations with one or more AI characters. It lets you choose who you speak as, choose who answers, organize conversations into forums, and keep useful sessions.

CHA runs as a small service called chaweb. You use the application in a web browser. The service stores your workspace and conversations in a local database and sends prompts to the AI provider selected for each character.

CHA is intended for personal use. It does not replace professional medical, legal, financial, or emergency advice.

2. Getting started

Open CHA

  1. Make sure the CHA service is running.
  2. Open the address given by the person who installed CHA. On the same computer, the address is often http://localhost:8086.
  3. CHA opens the Welcome session. You can start typing immediately or choose another forum or saved session from the sidebar.

The Welcome session is temporary. It is useful for a quick conversation, but it disappears when the CHA service stops. Create a normal session in a forum when you want the conversation to be saved.

Send your first message

  1. Click the message box at the bottom of the chat.
  2. Type your message.
  3. Press Ctrl+Enter, or select the Send button.

Pressing Enter by itself adds a new line. This makes it easy to write a message with several paragraphs before sending it.

Make the message box larger

Drag the divider above the message box upward or downward. The box can use up to 80% of the chat height. When the divider has keyboard focus, use the Up and Down arrow keys to resize it. Press Home or double-click the divider to return to the automatic size.

3. The four main ideas

How CHA organizes a conversation
Item What it means Example
Persona The identity and background you use when speaking. You, a guest, or a role created for a particular kind of discussion.
Character The AI counterpart that replies, together with its instructions and provider settings. A general assistant, tutor, editor, or historical voice.
Forum A group of characters and the default persona used with them. A study group or a collection of advisers.
Session One saved conversation inside a forum. “Planning the autumn trip.”

A forum provides the setting. A persona says who is asking. A character says who answers. A session contains the actual conversation.

4. Finding your way around

The sidebar contains four main areas:

  • Personas shows the available speaking identities and their descriptions. Opening a persona here does not change your current persona.
  • Characters shows the available AI characters. Select one to read its description or, when allowed, change its settings.
  • Forums shows groups of characters. Open a forum to see its members, active persona, and saved sessions.
  • Recent gives quick access to recently used sessions.

On a small screen, open the sidebar when you need it and close it to give the conversation more room.

5. Creating and managing sessions

Create a saved session

  1. Open Forums in the sidebar.
  2. Select the forum you want to use.
  3. Select New session.
  4. Enter a title when requested, then begin the conversation.

Open an earlier session

Select a session under Recent, or open its forum and choose it from the session list. Sessions in a forum are shown with the most recently used items first.

Rename, download, or delete

Open the action menu beside a session in the Recent list. Choose:

  • Rename to change the displayed title.
  • Download to save a Markdown copy.
  • Delete to remove the session from CHA.

A deleted session can no longer be opened in the browser. Download it first if you may need a readable copy later.

Using the same session in two browsers

Only one browser connection controls a live session. If you open the same session on another device or browser tab, the newest page takes control. The older page may need to reconnect or be refreshed.

6. Having a conversation

See who is speaking

The information above the message box shows the forum, the persona in the From position, and the character in the To position. Check this line before sending if the forum has several members.

Choose one character for a message

Start a message with @Name to address a particular character: 

@Seneca How should I think about this setback?

CHA accepts an unambiguous full name, identifier, or partial name without regard to letter case. To start ordinary text with a literal at sign, type two at signs: @@example becomes @example.

Ask several characters

Use /mcast to send one prompt to several forum members: 

/mcast @Seneca @Epictetus What matters most here?

CHA shows the shared question once. A horizontal line separates each reply, so it remains clear where one answer ends and the next begins.

Record a message without an AI reply

Start a message with @- to add it to the conversation without asking a character to respond: 

@- I made the decision this morning.

The note is saved in the shared history. A character selected later can use it as context. Use /@- to stay in recording mode until you choose a character again.

Stop a reply

While CHA is generating an answer, the Send button changes to Stop. Select it to stop generation. You can also use the /stop command.

Write in any language

Enter text directly in the language you want to use. For a different alphabet or keyboard layout, use the normal input settings provided by your computer or phone.

7. Chat commands

Commands begin with a slash and are entered in the same box as an ordinary message. The following commands are available during a session.

Session commands
Command Purpose Example or note
/clear Clear the current transcript and begin with an empty conversation. Use with care if you still need the earlier exchange.
/cover Keep earlier messages visible, but leave them out of later AI requests. Useful when the conversation has changed subject.
/uncover Return covered messages to the context used for future replies.  
/mcast Send one prompt to more than one character. /mcast @One @Two Your question
/info Show information about the current session.  
/characters List the characters in the current forum. /agents is an older name for the same command.
/@Name Choose the default character and save that choice for the forum. /@Seneca
/@- Enter recording mode, in which messages are saved without AI replies. This choice applies only to the current session.
/!Name Choose your persona and save that choice for the forum. /!Michael
/style name Change the conversation's visual text style for this session. Use /style to see the current style and /style default to restore it.
/stop Stop the reply that is being generated.  
/exit Close the live session. You can open a saved session again later.

8. Character settings

Open Characters, select a character, and then open Settings. The Settings option appears only for characters that can be changed. The built-in Assistant does not have this screen.

Settings available in the browser
Setting Meaning
Provider The AI service and model used by this character.
Reasoning effort How much internal work the model may do before answering. Higher settings can take longer and may cost more.
Web search Whether the character may search the web, must search it, or must not search it.
Style The font treatment used to display this character's messages.

Saving character settings restarts live sessions that use the character. If a reply is being generated, that unfinished reply will be lost.

9. Downloading conversations

Use Download in a session's action menu to save a Markdown file. Markdown is plain text that remains readable in an ordinary text editor and is also supported by many note-taking applications.

The exported file is designed to be compact:

  • The session start time appears once near the beginning.
  • Each speaker is shown as a monospace badge followed by a middle dot.
  • Paragraphs within one reply stay close together.
  • A small gap separates one message from the next.
<!-- CHA session: An evening conversation -->
*Started September 03, 2026 at 17:47 PDT*

`Michael` · How can I make better use of the rest of today?

`Montaigne` · Begin by deciding whether you need rest or attention.  
Then choose one small act and do it completely.

An administrator may also enable a Markdown mirror. When enabled, CHA keeps an additional plain-text copy of persistent sessions in folders named after their forums. The database remains the main copy used by CHA.

10. Privacy and data

  • Saved sessions and workspace settings are stored in the SQLite database named in the application configuration.
  • Prompts and the needed conversation history are sent to the configured AI provider when you request a reply.
  • If web search is enabled, the provider may use the web to prepare an answer. CHA stores the final answer, not the provider's search details.
  • A Markdown mirror, if enabled, creates readable copies of conversations on disk. Treat that folder as private.

Protect the database, configuration, environment file, log files, and Markdown mirror. They can contain private conversations or access keys.

11. Troubleshooting

Common problems
Problem What to try
The browser cannot open CHA. Confirm that chaweb is running, check the configured host and port, and look in chaweb.log or the configured application log.
A reply fails immediately. Check that the selected provider is correct and that its API key environment variable is available to CHA.
A reply stops during generation. Check the network connection and provider status, then send the message again. An administrator can also review timeout settings and logs.
The wrong character answers. Check the To value above the message box. Use /@Name to choose a default or begin one message with @Name.
The wrong persona is shown. Check the From value and use /!Name to choose another persona.
Typing Enter sends nothing. This is expected. Enter adds a new line; use Ctrl+Enter or the Send button.
An older browser tab disconnected. Another tab or device probably opened the same session. Continue in the newest page, or refresh the page you want to use.
Changes to files do not appear. Configuration files are imported into the database. Stop CHA and import the workspace again; editing an old import folder alone does not change the running application.

Appendix A

Configuration reference

This appendix is for the person who installs or maintains CHA. Everyday use of the application does not require these settings.

A.1 Main configuration file

CHA reads a TOML configuration file. In a packaged installation, copy cha.toml.example to a safe location outside the application directory and edit the copy. A basic file looks like this: 

data = "cha.sqlite3"
# mirror = "session-mirror"

[web]
host = "0.0.0.0"
port = 8086

[logging]
file = "logs/cha.log"
level = "info"
Main configuration settings
Setting Required Meaning
data Yes Path to the SQLite database used by CHA.
mirror No Existing directory where CHA keeps additional Markdown copies of persistent sessions.
web.host Yes Network address on which the web service listens. 0.0.0.0 allows connections through any available network interface.
web.port Yes Web service port, from 1 through 65535.
logging.file Yes File that receives application log messages.
logging.level Yes Detail level: trace, debug, info, warn, error, critical, or off.

Relative paths in data, mirror, and logging.file are resolved from the directory containing the main configuration file. The mirror directory must already exist.

A.2 Starting a packaged installation

A typical first installation uses these steps:

cd /path/to/cha-package
cp cha.toml.example ../cha.toml
# Edit ../cha.toml and import-seed/.env as needed.
./chaweb --config=../cha.toml --import ./import-seed
./start-cha.sh

The import creates and fills the database. Normal startup expects an initialized database; it does not create an empty workspace by itself. The start script runs chaweb in the background and writes its console output to chaweb.log beside the executable.

Choose another configuration file

By default, start-cha.sh uses ../cha.toml. Set CHA_CONFIG to use another file: 

CHA_CONFIG=/etc/cha/cha.toml ./start-cha.sh

An absolute path is used directly. A relative path is interpreted from the directory containing start-cha.sh.

A.3 Environment variables and secrets

Environment variables used by CHA
Variable Purpose
CHA_CONFIG Overrides the configuration file used by start-cha.sh.
OPENAI_API_KEY A common API key variable. The actual name is chosen by each provider's api_key_env setting.
CHA_R2_URL Cloudflare R2 endpoint and bucket used for database upload or download.
CHA_R2_ACCESS_KEY_ID Access key for R2 synchronization.
CHA_R2_SECRET_ACCESS_KEY Secret key for R2 synchronization.

Provider keys can be inherited from the operating-system environment or read from a root .env file during import. An inherited value takes precedence. Never commit a real .env file or API key to source control.

A.4 Workspace files

Personas, characters, forums, providers, styles, and prompt text are imported into the database from a workspace directory. A typical layout is: 

workspace/
  .env
  characters/
    assistant-name/
      character.toml
      CHARACTER.md
  personas/
    persona-name/
      persona.toml
      PERSONA.md
  forums/
    forum-name/
      config.toml
      FORUM.md
      members/
  system/
    providers/
    styles/

Only regular TOML and Markdown files are imported, together with the optional root .env file. Symbolic links are not followed. Directory names act as stable identifiers, so use short, distinct names.

Character settings

display_name = "Montaigne"
description = "A reflective conversation partner"
provider = "openai"
style = "book"
reasoning_effort = "medium"
web_search = "auto"
tags = ["philosophy"]

[prompt]
language = "English"
characters/<id>/character.toml
Setting Required Allowed values or meaning
display_nameYesName shown in CHA.
providerYesIdentifier of a configured provider.
descriptionNoShort description shown to the user.
styleNoIdentifier of a configured display style.
reasoning_effortNolow, medium, high, or xhigh.
web_searchNooff, auto, or required.
tagsNoA list of labels used to describe the character.
[prompt]NoValues substituted into prompt templates.

CHARACTER.md contains the character's main instructions. Keep them clear, specific, and suitable for the intended conversations.

Persona settings

display_name = "Michael"
description = "My everyday speaking persona"
personas/<id>/persona.toml
SettingRequiredMeaning
display_nameYesName shown in CHA.
descriptionNoShort explanation of the persona.

PERSONA.md is optional and can provide background that helps characters understand the speaker. CHA also provides a built-in Guest persona.

Forum settings

display_name = "Philosophers"
description = "Conversations about practical philosophy"
default_character = "montaigne"
default_persona = "michael"
forums/<id>/config.toml
SettingRequiredMeaning
display_nameYesName shown in CHA.
descriptionNoShort explanation of the forum.
default_characterNoCharacter selected when a session begins. It must be a forum member.
default_personaNoPersona selected when a session begins. Guest is used when this is omitted.

Forum members are listed under forums/<id>/members. FORUM.md contains forum-level instructions. The optional members/character_defaults.toml file provides prompt values shared by the forum's characters.

Provider settings

Provider files are stored below system/providers. The exact folder structure in the supplied workspace can be used as a template. 

host = "api.openai.com"
port = 443
https = true
base_path = "/v1"
model = "model-name"
api = "responses"
mode = "net"
stream = true
api_key_env = "OPENAI_API_KEY"
timeout_s = 600
idle_timeout_s = 60
web_search = "off"
Provider configuration
SettingDefaultMeaning
hostRequiredProvider server name.
portRequiredProvider server port, from 1 through 65535.
modelRequiredModel name sent to the provider.
httpsfalseUse a secure HTTPS connection when true.
base_pathEmptyURL path before the API endpoint. If present, it begins with /.
apiresponsesresponses or chat_completions.
modetestnet makes real requests. test is a local test mode.
streamtrueShow the answer as it arrives.
temperatureProvider defaultOptional value from 0 through 2 controlling variation.
max_tokensProvider defaultOptional positive answer-length limit.
timeout_s600Maximum total request time in seconds.
idle_timeout_s60Maximum wait between received pieces of a streamed answer.
api_key_envEmptyName of the environment variable holding the API key.
reasoning_effortProvider defaultDefault reasoning effort sent to the provider.
reasoning_formatautoauto, none, reasoning_content, or reasoning.
web_searchoffoff, auto, or required.
cache_retentionshortoff, short, or long, when supported by the provider.

Use mode = "net" for normal conversations. Web search works only with provider and API combinations that support it.

Display style settings

A style is defined in system/styles/<id>/config.toml. It changes presentation only; it does not change what a character says. 

font = "serif"
style = "normal"
weight = "medium"
size = "normal"
text_color = "normal"
Allowed style values
SettingAllowed values
fontsans, serif, mono
stylenormal, italic
weightlight, normal, medium, semibold, bold
sizesmall, normal, large
text_colornormal, muted, accent

Prompt templates

Markdown prompt files can reuse text and values. Use $$(relative/file) to include another file and $${variable} to insert a value from a prompt settings table. Keep templates small and test them after import.

A.5 Import, export, and maintenance

Stop the running service before an offline import, export, upload, or download. These modes cannot be combined in one command.

chaweb commands
CommandPurpose
chaweb --config=CONFIG --root PATHStart CHA and optionally use PATH for web application files.
chaweb --config=CONFIG --import DIRECTORYImport workspace files into the database.
chaweb --config=CONFIG --export DIRECTORYExport the database configuration to an empty or missing directory.
chaweb --config=CONFIG --uploadUpload the database to the configured R2 bucket.
chaweb --config=CONFIG --downloadDownload the database from R2. The previous local database is backed up with a .bac suffix.

A safe configuration-editing cycle is:

  1. Stop CHA.
  2. Export the current workspace to a new, empty directory.
  3. Edit the exported TOML and Markdown files.
  4. Keep a backup of the database.
  5. Import the edited workspace.
  6. Start CHA and test the change.
./chaweb --config=/path/cha.toml --export /path/exported-workspace
# Edit the exported files.
./chaweb --config=/path/cha.toml --import /path/exported-workspace

A.6 R2 database backup

Set the three CHA_R2_... environment variables described in section A.3, then use --upload or --download. The R2 URL has this form: 

CHA_R2_URL=https://ACCOUNT_ID.r2.cloudflarestorage.com/BUCKET

The object name is the database file name. Test backup and restore before relying on them, and keep the R2 credentials private.
