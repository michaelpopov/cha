User guide · web edition

Many minds, one room at a time.

CHA is a personal place for conversations with AI characters. You decide who you are speaking as, who is in the room, and what kind of conversation the room is meant to hold.

Start with one conversation → Create a character Borrow a scenario

01 · The idea

A conversation studio, not just a chat box

A normal chatbot gives you one general assistant. CHA lets you build a small world of distinct participants and return to their conversations over time.

Think with contrasting voices

Ask a careful planner, a skeptical critic, and an imaginative explorer to look at the same decision. Their differences are often more useful than one polished consensus.

Create durable contexts

Keep a forum for a book project, another for career reflection, and another for language practice. Each forum carries its own cast and shared instructions.

Return to an ongoing thread

Named sessions preserve their transcripts. Reopen an old design review, continue a long correspondence, or download the conversation as Markdown.

Shape the relationship

A persona tells characters who is speaking. A character definition shapes who answers. A forum tells everyone what kind of room they are in.

Welcome is your safe starting point

When CHA opens, you arrive in Entrance / Welcome as the built-in Guest, speaking with Assistant. Welcome is temporary and disappears when the server stops. Sessions you create inside your own forums are stored.

02 · The mental model

From, to, where—and the conversation itself

These four pieces unlock the whole application. If a reply feels wrong, ask which piece should change.

From

Persona

Who you are speaking as: Guest, a project lead, yourself, a fictional narrator, or any useful point of view.

To

Character

The AI participant answering you, with a defined identity, temperament, expertise, and conversational voice.

Where

Forum

The room: its purpose, house rules, shared context, persona, and roster of available characters.

Record

Session

One named, saved conversation inside a forum. A forum may hold many sessions with the same cast.

Persona→Character@Forum→Session

03 · First steps

Start a useful conversation in a minute

If your workspace already has a forum, you can begin without configuring anything.

01

Choose a forum

Open the sidebar and select Forums. Each row shows a forum name and either its description or its cast.

02

Open or create a session

Select the forum, then open an existing session or choose New session. Give it a useful name such as “Launch decision” or “Chapter 3”.

03

Check From and To

The status line below the message box shows the forum, the persona after From:, and the current character after To:.

04

Send a message

Press Enter to send. Use Ctrl+Enter for a new line. While a reply is arriving, the send button becomes a stop button.

Useful chat controls

  • Use the target menu beside the message box to switch the forum’s default character.
  • Start a message with @Name to address one character for that message without changing the default.
  • If a microphone button appears, you can dictate into the draft before sending.
  • The message editor grows as you type; drag its top edge to resize it manually.
  • Recent sessions appear in the sidebar. Their … menu can download, rename, or delete them.
Deletion means deletion

Deleting a session removes it from CHA. Deleting a forum removes the forum and all sessions inside it. Download any transcript you want to keep first.

04 · Personas

Give the conversation a clear “you”

A persona describes the human side of the exchange. It can tell characters your background, priorities, preferred style of help, or the role you are playing today. Your messages appear under that persona’s name.

Opening a persona in the Personas list only shows its profile—it does not activate it.

Create a persona in the web UI

Personas›New persona›Name›Create persona
  1. Enter a display name such as “Maya — Product Lead”.
  2. On the new persona’s page, choose the text-lines button in the top bar to edit its profile, or the upload button to replace it from a Markdown or text file.
  3. In a session, type /!Maya (or another unambiguous part of the name) to speak as that persona. This also saves it as the forum’s default persona.
Write for relevance, not biography

A few details that improve answers are better than a life story. Include what you are trying to do, what you know already, what tends not to help, and how candid or structured you want the conversation to be.

# Maya — product lead

I lead a small team building tools for researchers.
I know the product well but I am not an infrastructure
expert.

Help me separate user value from implementation fashion.
Challenge vague success criteria. Prefer one concrete
next experiment over a long programme of work.

I welcome direct disagreement, but explain technical
trade-offs in plain language.

Persona profiles become part of the context sent to the selected model provider. Do not put passwords, API keys, or information you would not want included in a model request.

05 · Characters

Create someone worth talking to

A good character is not merely “helpful.” It notices particular things, values some evidence over other evidence, has a recognizable way of reasoning, and is allowed to disagree.

Characters›New character›Name + description›Create character

1. Name the promise

The short description appears in the character list. Make it tell you why this participant belongs in your cast: “A skeptical editor who finds unsupported leaps,” not “A helpful assistant.”

2. Write the definition

After creation, the definition is blank. Use the text-lines button in the top bar to edit it, or upload a Markdown/text file. Describe the character directly: identity, attention, values, manner, limits, and behavior.

3. Choose a provider

Open Settings on the character page. Select an available provider. Optionally choose reasoning effort, web search behavior, and a visual style. A new character needs a provider before it can answer.

4. Put them in a forum

Open the forum, select its name above the session list, choose Members, check the character, and save. At least one character must remain in every forum.

# Rowan, the skeptical editor

You are Rowan, an experienced developmental editor.
You care about the reader's attention more than the
author's attachment to a passage.

Notice unsupported claims, buried stakes, false urgency,
and places where elegant prose is doing the work of an
argument. Ask what the piece is truly trying to change in
the reader.

Be candid but not theatrical. Do not rewrite everything.
Identify the one revision that would improve the piece
most, explain why, and wait for the author's response.

A richer historical-character recipe

For a historical thinker, describe more than famous quotations. Include their circumstances, tensions, habits of attention, blind spots, characteristic arguments, and what they could not honestly know. Ask them to reason from inside their worldview rather than announce “As X, I would…”.

Saving character settings restarts affected sessions

If a character is answering, that answer can be lost. Finish or stop the current reply before changing the character’s provider, reasoning, search, or style settings.

06 · Forums

Design the room, then invite the cast

A forum is a reusable conversational setting. Its description is also shared instruction for the characters in that forum, so it can establish a purpose, relationship, procedure, or house rules.

Forums›New forum›Name + persona›Create forum
  1. Choose the persona that will speak in the forum.
  2. The forum begins with the built-in Assistant as its only member, so it is immediately usable.
  3. Click the forum name above its session list to open the forum page.
  4. Use the text-lines button to write the forum description. Use Members to add or remove characters.
  5. Choose a default character from the chat target menu, or type /@Name in a session.
# Decision Room

This forum exists to improve consequential decisions,
not to manufacture agreement.

Separate facts, assumptions, values, and reversible bets.
Each character should contribute the concern most native
to their point of view. Do not repeat another character's
argument merely to sound complete.

When the decision is mature, help the persona state:
the choice, the reason, the main risk, and the next check.

Three forum patterns that work well

A standing council

Keep the same complementary cast for recurring decisions: a domain expert, a skeptic, and a practical operator.

A project room

Give a forum one body of work and open a session per topic: research questions, outline, draft review, launch notes.

A salon

Bring together characters with real philosophical or aesthetic differences and ask questions without forcing consensus.

A rehearsal room

Create characters representing an interviewer, stakeholder, customer, or critic, then practice difficult exchanges.

07 · Conversation craft

Let the cast disagree productively

The most interesting CHA conversations use the shared transcript. Characters can see relevant contributions from the other forum members, so later replies can challenge, sharpen, or extend what has already been said.

You · Maya

/mcast @Rowan @Inez We have six weeks. Should we cut onboarding research and build the requested dashboard now?

Rowan · skeptic

You have framed research as delay and building as progress. What evidence says the dashboard is the obstacle?

Inez · operator

Six weeks is enough for neither certainty nor a broad build. Interview five recent drop-offs, then prototype the narrowest disputed workflow.

You · Maya

@Rowan Assume the request came from our largest customer. What would change your objection?

08 · Ready-made ideas

Six conversations to make your own

Mix original roles, historical figures, and practical specialists. The prompt is only a doorway; follow whichever answer makes the conversation more interesting.

SCENARIO 01

The pre-mortem council

Explore a plan as though it has already failed. Let each character find a different failure mode.

Cast: Operator · Skeptic · Customer advocate
“It is six months from now and this launch failed. Give me the most plausible story of what happened—and the earliest sign we ignored.”
SCENARIO 02

The manuscript table

Separate structural, reader, and sentence-level feedback instead of asking one general editor to do everything.

Cast: Developmental editor · Curious reader · Stylist
“Do not rewrite this yet. Tell me where your attention rises, where it drops, and what promise the opening seems to make.”
SCENARIO 03

A historical salon

Give historical characters grounded profiles and let their genuine differences emerge around a modern problem.

Cast: Seneca · Epictetus · Marcus Aurelius
“My work is successful, but I resent how much of my attention it owns. Which part of this is fortune—and which part is my consent?”
SCENARIO 04

The architecture review

Make trade-offs visible before code hardens them into facts.

Cast: Minimalist architect · Reliability engineer · Future maintainer
“Here is the smallest design I think will work. Which failure deserves prevention now, and which complexity should wait for evidence?”
SCENARIO 05

The difficult rehearsal

Practice a conversation with a character who has believable goals rather than one trained to be agreeable.

Cast: Impatient executive · Trusted peer coach
“You believe my proposal is too slow and too cautious. Challenge me as you would in the meeting; pause after each objection so I can answer.”
SCENARIO 06

The curiosity walk

Use a warm but opinionated character to turn an ordinary observation into a surprising line of inquiry.

Cast: Naturalist · Urban historian · Childlike questioner
“I noticed three different kinds of moss on one wall today. Ask me questions that could turn that small observation into an hour of exploration.”

09 · Behind the scenes

Three settings, lightly explained

If CHA already answers successfully, you can leave these alone. They exist so different characters and workspaces can behave differently.

Providers choose the model connection

A provider names the endpoint, model, and default inference behavior used by a character. Each character selects one provider in its Settings. API keys are managed separately under Settings → API Keys.

Vaults keep worlds separate

A vault is a separate CHA database and workspace. Use the selector at the bottom of the sidebar to switch. A personal vault and a project vault can have different forums, characters, and sessions.

Styles change appearance, not thought

A style is a reusable typography and color preset for character messages. It helps you recognize voices visually; it does not change the character’s personality or model.

A little more about providers

Most users only need to pick an existing provider on a character’s Settings screen. Reasoning effort and web search can inherit the provider default or be overridden for that character. Web search must be supported by the selected provider.

A little more about vaults

Vault settings can also name optional mirror and editable-workspace paths. Those are advanced storage features. Creating a vault can start empty or copy an existing vault; creating it does not automatically switch to it.

A little more about styles

Styles combine a font family, slant, weight, size, and text color. Use /style name for a session-only appearance override, /style to report the current override, and /style default to return to the configured style.

10 · Keep nearby

Chat command card

Commands must begin at the very start of the message. Names may be a full display name, an unambiguous part of one, or a character/persona ID.

CommandEffect
/clearClear the session transcript.
/cover / /uncoverHide earlier conversation from model context, or restore it.
/mcast @A @B questionSend the same prompt to several forum characters.
/infoShow information about the current session.
/charactersList the characters in this forum. /agents is an older alias.
/@NameChoose and save the forum’s default character.
/@-Enter recording mode: save messages without generating replies.
/!NameChoose and save the forum’s persona.
/style nameOverride the current character’s appearance for this session only.
/stopStop the current generation.
/exitClose the live session. The stored conversation remains saved.
@@exampleSend literal text beginning with an at-sign.
Small edits can have wide effects

Changing a character definition, persona profile, forum description, membership, provider, or style may restart related live sessions. Finish important in-progress answers before editing shared configuration.

The built-in Guest, Assistant, and Entrance are read-only. Before deleting one of your own characters, remove it from every forum. Before deleting a persona, make sure no forum is using it.
