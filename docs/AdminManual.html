It is the companion of the CHA User Manual. The User Manual describes daily use: conversations, notes, voice and the Library. Where the User Manual has a line that starts with Setup:, this manual gives the procedure. Chapter 33 lists these lines and the sections that answer them.

1. About this manual

In this chapter
  • The reader
  • Terms
  • Conventions
  • External services

The reader

This manual is for the person who installs CHA and keeps it in operation. You must know how to:

  • Extract an archive and start an application.
  • Edit a text file.
  • Create an account and an API key at an external service.

Only the chapter ChaWeb needs more: work in a Linux terminal, systemd, nginx and TLS certificates.

Terms

Term Meaning
Configuration directory The directory where CHA keeps app.toml, the vaults, and the log. See First start.
Vault One complete set of data: configuration, sessions and notes. A vault is one database file and one definition file.
Configuration The personas, characters, forums, providers, styles, voices, saved keys and service settings of one vault. CHA keeps the configuration in the vault database, not in files.
Active vault The vault that is open. The Settings screens show and change the active vault.
Main process The first CHA process that opens a vault. Only the main process can change settings. See More than one CHA process.
ID The internal name of an item, for example character_3. An ID does not change when you rename the item.

Conventions

  • Bold text is a label that the application shows.
  • Monospace text is a file name, a key, a value or a command.
  • Text in angle brackets is a placeholder. Replace <vault name> with your value. Do not type the brackets.
  • Settings → Vaults means: click Settings, then click Vaults.

External services

CHA uses external services for models, voices, web search, cloud stores, and the transfer of vaults. For each service, this manual tells you what CHA needs: the fields, the form of an address, and the objects that you must create. It does not describe the web sites of the services. Each service has its own prices and its own terms.

2. Install CHA on macOS

In this chapter
  • Requirements
  • Install
  • Where CHA keeps its data
  • Microphone
  • Update and remove

Requirements

  • A Mac with Apple Silicon. The package does not run on a Mac with an Intel processor.
  • The macOS version of the computer that made the package, or a later version. The oldest possible version is macOS 13.3.

Install

The package is the file CHA-macos-<version>.tar.gz. It contains only CHA.app. There is no installer.

  1. Extract the archive.
  2. Move CHA.app to the Applications folder, or to a different folder.
  3. Start CHA.

The application has an ad hoc signature and is not notarized. macOS can refuse to open it until you approve it.

Where CHA keeps its data

The configuration directory is:

~/Library/Application Support/CHA

You cannot select a different directory. CHA does not accept command-line arguments.

Microphone

The first time you use voice input, macOS asks for access to the microphone. If you refuse, voice input shows Microphone access was denied. Allow it in System Settings and try again.

Update and remove

  • To update, close CHA and replace CHA.app with the new one. The configuration directory does not change.
  • To remove the application, delete CHA.app. To remove all data too, delete the configuration directory.

3. Install CHA on Windows

In this chapter
  • Requirements
  • Install
  • Where CHA keeps its data
  • Update and remove

Requirements

  • A 64-bit (x64) version of Windows 10 or Windows 11.
  • The Microsoft Edge WebView2 Runtime (the Evergreen version). If it is not installed, CHA shows Failed to initialize WebView2 or The Microsoft Edge WebView2 Runtime could not start.

Install

The package is the file CHA-windows-<version>-x64.zip. It contains the folder CHA-windows-x64 with CHA.exe and the folder web. There is no installer. CHA makes no shortcuts and no registry entries.

  1. Extract the archive to a folder of your choice.
  2. Keep CHA.exe and the folder web together. CHA reads its screens from web.
  3. Start CHA.exe.

The package is not signed. Windows can show a warning when you start it.

CHA does not need administrator rights.

Where CHA keeps its data

Directory Content
%LOCALAPPDATA%\CHA\config The configuration directory.
%LOCALAPPDATA%\CHA\webview Data of the WebView2 component.

You cannot select a different directory. CHA does not accept command-line arguments.

Update and remove

  • To update, close CHA and replace the folder CHA-windows-x64 with the new one.
  • To remove the application, delete that folder. To remove all data too, delete %LOCALAPPDATA%\CHA.

4. First start

In this chapter
  • What CHA creates
  • If CHA cannot start
  • Start with a protected vault
  • More than one CHA process

What CHA creates

When the configuration directory is empty, CHA creates these items in it:

Item Content
app.toml The application settings. See app.toml.
default.toml The definition of the vault Default.
default.sqlite3 The database of the vault Default.
mirror/ The base directory for readable copies of sessions.
modify/ The base directory for the export and import of configuration.
logs/cha.log The log.

The first app.toml has this content:

vault = "Default"

mirror = "mirror"
modify = "modify"

[logging]
file = "logs/cha.log"
level = "info"

The vault Default contains:

  • The built-in character Assistant.
  • One provider with the ID chatgpt. It uses a ChatGPT subscription. It works only after you connect a ChatGPT account. See Connect a ChatGPT account.

It contains no forums, no other characters and no API keys.

CHA then shows the Welcome session. See the User Manual for the built-in forum Entrance and the session Welcome.

If CHA cannot start

A start error shows in a dialog with the title CHA cannot continue. The most frequent causes are:

  • The configuration directory is not empty, but it has no app.toml. CHA creates the first configuration only in an empty directory. The message is Failed to read application config with the path of the file.
  • app.toml or a vault definition file has an error. See app.toml and Vault definition files.
  • A .toml file that is not a vault definition is in the configuration directory. CHA reads each .toml file in that directory, other than app.toml, as a vault definition.

Start with a protected vault

If the vault in app.toml has a password, a dialog with the title Open vault and the name of the vault shows before the screens of the application load. Type the password and click Open vault. Quit stops the start. CHA does not store the password.

More than one CHA process

On macOS, Window → New Instance starts a second CHA process. On Windows, a second start of CHA.exe does the same. ChaWeb is one more process when it uses the same vault on the same computer.

For each vault, the first process that opens it is the main process. Each later process is a secondary process. A secondary process keeps this role until it opens a vault again.

A secondary process has these limits:

  • It cannot change settings. The message is Settings can be changed only in the main CHA process. This includes all Settings screens, the vault commands, and the upload to a store.
  • It cannot generate note audio. The message is Close other CHA processes using this vault, then try again.
  • It does not run D1 synchronization.
  • It does not write the session mirror.
  • It does not save the vault selection for the next start.

Two processes cannot have the same session open. The message is This session is open in another CHA process.

Some vault commands need all other processes to close the vault first. The message is Close other CHA processes using this vault, then try again.

5. Minimum setup for the first conversation

In this chapter
  • Step 1 — Make a provider work
  • Step 2 — Create a forum
  • Step 3 — Add your own characters

Before the first conversation, the vault must have a forum with a minimum of one character, and that character must have a provider that works.

A new forum has the Assistant as its first member. Thus the shortest path has two steps: make the provider of the Assistant work, then create a forum.

Step 1 — Make a provider work

Use one of these methods.

Method A: a ChatGPT subscription

  1. Click Settings.
  2. On the card OpenAI, click Connect ChatGPT and follow Connect a ChatGPT account.

The provider chatgpt of the first vault then works. The Assistant already uses it.

Method B: an API key

  1. Save the API key of your model service. See API keys.
  2. Create a provider that uses the key. See Create a provider.
  3. Click Test on the provider screen. The result must be Provider responded successfully.
  4. Select the new provider for the Assistant: Settings → Characters → Assistant → Character settings → Provider, then Save.

Step 2 — Create a forum

  1. Click Settings → Forums → New forum.
  2. Type a Name. In Persona, select Guest or a different persona.
  3. Click Create forum.

You can now start a session in this forum and talk to the Assistant. See “First steps” in the User Manual.

Step 3 — Add your own characters

  1. Create a character. See Create a character.
  2. Select a provider for the character in Character settings.
  3. Write the profile of the character.
  4. Add the character to the forum on the Members screen. See Members.

You can also ask the Assistant in the Welcome session to do these tasks. See The Assistant as a configuration tool.

Rules that apply to all Settings screens

  • The screens show and change the active vault. Each vault has its own configuration. The ChatGPT connection is the exception: it applies to all vaults of the computer.
  • Only the main process can change settings.
  • CHA makes a check of the full configuration before it saves a change. If the check fails, nothing changes, and the screen shows the error.
  • A change applies immediately. You do not have to restart CHA. Open sessions get the new configuration. Some changes, for example a new name, a new profile text or new members, start the open sessions of the forums that use the item again. An answer that is in work there is lost.
  • To rename an item, click its title, type the new name, and click the save button. A new name does not change the ID of the item. Thus all references to the item stay correct.
  • To delete an item, click the trash button or the Delete button on its screen and confirm. You cannot undo a deletion. CHA refuses to delete an item that is in use. Saved API keys are the exception.
  • The IDs that CHA makes have the form persona_<N>, character_<N>, forum_<N>, provider_<N>, style_<N>, voice_<N> and api_key_<N>.

7. API keys

In this chapter
  • Where CHA stores the keys
  • Save a key
  • Change or remove a key
  • R2 storage and D1 sync

An API key is a named secret for an external service. You save a key one time. Then you select it by its name in each place that needs it: a provider, the Search API, voice input, voice output, recipient detection, the note audio service, or a Library.

CHA has no field for the kind of service. The place that uses the key decides to which service CHA sends it.

Where CHA stores the keys

CHA stores each key in the database of the active vault. Each vault has its own keys.

CAUTION: In a vault without a password, the keys are in the database file as plain text. To encrypt them, protect the vault. See Protect a vault with a password. CHA does not use the macOS Keychain or the Windows credential store.

The keys go with the vault:

  • An R2 upload sends the full database, the keys included.
  • D1 synchronization sends the saved keys to the other computers. The D1 credentials are the exception.
  • Export writes all keys to files as plain text. See Configuration files.

After you save a key, no screen shows its value again.

Save a key

  1. Click Settings → API Keys → New API key.
  2. Type a Name, for example the name of the service.
  3. Paste the key into API key.
  4. Select Cloud store only if the key is for a Library. Select OpenAI or Gemini. For all other keys, keep None.
  5. Click Save API key.

Rules: the name has 1 to 100 bytes. The key has a maximum of 16,384 bytes. Neither can contain a line break. CHA does not refuse two keys with the same name. Use different names.

Change or remove a key

Click the key in the list.

  • To rename it, click the title.
  • To replace the secret, paste the new key into New API key and click Save.
  • To change Cloud store, select the value and click Save. You do not have to type the secret again.
  • To remove it, click Remove API key and confirm.

The list Used by shows the providers and functions that use the key. A forum Library and the note audio service do not show in this list.

CAUTION: CHA does not stop you when you remove a key that is in use. The functions that use it stop: a provider gives the error that the API key does not exist.

R2 storage and D1 sync

The first two rows of the API Keys screen are R2 storage and D1 sync. These are the credentials for the transfer of vaults. See R2 storage and D1 synchronization.

8. Providers and the ChatGPT connection

In this chapter
  • Supported API formats
  • Create a provider
  • Rules for the ChatGPT subscription
  • Reasoning effort, where it comes from
  • Rename and delete a provider
  • Connect a ChatGPT account

A provider is a connection to one model at one model service. A character gets its model from its provider. To let two characters use different models of the same service, create two providers.

Supported API formats

API format Use it for Address that CHA calls
Responses The OpenAI Responses API and services that are compatible with it. The ChatGPT subscription. <Base URL>/v1/responses
Chat completions Services with an OpenAI-compatible chat completions API, local model servers included. <Base URL>/v1/chat/completions
Google (Gemini) The Gemini API of Google. <Base URL>/models/<model>:streamGenerateContent
Anthropic The Anthropic Messages API. <Base URL>/v1/messages

Exceptions:

  • For the ChatGPT subscription, CHA always calls https://chatgpt.com/backend-api/codex/responses.
  • For Chat completions, when the Base URL ends with /v1beta/openai, CHA calls <Base URL>/chat/completions.

Examples of Base URL values:

Service API format Base URL
OpenAI API Responses https://api.openai.com
ChatGPT subscription Responses https://chatgpt.com/backend-api/codex
Anthropic API Anthropic https://api.anthropic.com
Gemini API Google (Gemini) https://generativelanguage.googleapis.com/v1beta
OpenRouter Responses or Chat completions https://openrouter.ai/api
A local model server Chat completions http://<host>:<port>

Create a provider

  1. Click Settings → Providers → New provider.

  2. Type a Name.

  3. In Initial settings, select Default provider settings, or select Copy provider name to start from an existing provider. A copy also takes the key selection of that provider.

  4. Click Create provider. The provider screen opens.

  5. Set the fields:

    Field Value
    Model The model name, as the service defines it.
    Reasoning effort None, Low, Medium, High or Extra high. The field does not show for Google (Gemini) and Anthropic.
    Base URL The address of the service, without the API path. See the table above.
    API format See the table above.
    Credentials No credentials, OpenAI OAuth (the ChatGPT connection), or a saved API key.
    Inference targets Shows only when the host of the Base URL is openrouter.ai and the format is Responses or Chat completions. Type one OpenRouter provider name on each line to send requests only to those providers.

  6. Click Test. CHA sends one short request with the values on the screen. The result is Provider responded successfully. or Provider test failed: with the reason.

  7. Click Save changes.

A new provider with the default settings has the address https://api.openai.com, the model gpt-5, the format Responses, and no credentials.

A provider can have more settings than the screen shows, for example a temperature, an output limit and time limits. You can change them only in the configuration files. Save changes sets some of them again. See system/providers.

Rules for the ChatGPT subscription

A provider with Credentials = OpenAI OAuth must have the Base URL https://chatgpt.com/backend-api/codex and the API format Responses. CHA refuses other values. This selection is not available for Google (Gemini) and Anthropic.

Reasoning effort, where it comes from

The provider gives the start value. A character can replace it (Character settings → Reasoning effort). A user can replace it for one session with the Effort list of the chat toolbar.

Providers with the format Google (Gemini) or Anthropic ignore all reasoning effort settings.

Rename and delete a provider

A new name is safe. All references use the ID.

CHA refuses to delete a provider with the message This provider is still in use. when one of these uses it:

  • A character. The list Used by shows the characters.
  • Session naming in Session settings.
  • The Compression provider in Notes settings.

CHA does not refuse the deletion when only a forum Library uses the provider as its Default provider. The Library then ignores that selection, and the log gets a warning.

Connect a ChatGPT account

This connection lets providers with OpenAI OAuth use a ChatGPT subscription. CHA can have one connected account. The connection applies to all vaults of this computer.

  1. Click Settings. The card OpenAI shows Not connected.
  2. Click Connect ChatGPT. The card shows Waiting for approval, a link to the ChatGPT device page, and a code.
  3. Open the link in a web browser. Sign in, and type the code.
  4. Approve the access. The card shows Connected to ChatGPT.

A connection attempt stops after 15 minutes. To stop it earlier, click Cancel.

To remove the connection, click Disconnect.

CHA stores the connection in the file openai-auth.json in the configuration directory. The file is not part of a vault. A vault transfer and an export do not include it. Treat this file as a secret.

CHA renews the connection automatically. If the service refuses the renewal, CHA removes the connection, and requests fail with Sign in to ChatGPT before using this provider. Connect again.

For a server without a web browser, see Connect a ChatGPT account on the server.

9. Personas

In this chapter
  • The persona Guest
  • Create a persona
  • Rules for names
  • Persona settings
  • Delete a persona
  • Select the persona of a forum

A persona is the identity that the user speaks as in a forum. Each forum has one persona. The characters get the name and the profile of the persona as a description of the person that they talk to.

The persona Guest

Guest is built in. You cannot change or delete it. Select Guest for a forum that needs no special persona.

Create a persona

  1. Click Settings → Personas → New persona.
  2. Type the Persona name.
  3. Click Create persona. The persona screen opens.
  4. Click Edit persona profile and write the profile: who this person is, and what the characters must know about the person. Click Save. The upload button next to it replaces the profile with the content of a Markdown or text file.

Rules for names

The names of personas and characters must be different from each other. Capital letters do not make a name different. A name:

  • Cannot be empty, and cannot start or end with a space.
  • Cannot start with @ or /.
  • Cannot be one of these words: persona, system, error, human, assistant, agent, character, you, guest.

When a name is not permitted, the screen shows only Invalid persona. or Invalid character.

Persona settings

On the persona screen, click Settings. The only field is Style. It sets how the messages of this persona look in the conversation. See Styles.

Delete a persona

CHA refuses to delete a persona that a forum uses: This persona is still used by one or more forums. Select a different persona for those forums first.

Select the persona of a forum

  • For a new forum: the Persona list on the New forum screen.
  • For an existing forum: the Persona list on the Members screen. See Members.

10. Characters

  • Character settings
  • The profile and the instructions
  • Files
  • Nicknames

A character is an AI participant. It has:

  • A name and a short description.
  • Character settings: provider, reasoning effort, web search, style and voice.
  • A profile: the text that tells the model who the character is.
  • Optional files: more text, nicknames and pictures.

Create a character

  1. Click Settings → Characters → New character.
  2. Type a Name and a Description. The description is a short line for the lists. You cannot change it later on the screens.
  3. Click Create character. The character screen opens.
  4. Click Character settings, select a Provider, and click Save.
  5. Go back to the character screen. Click Edit character profile, write the profile, and click Save.

A character without a provider is a draft. You cannot add a draft to a forum.

The rules for names are the same as for personas. See Rules for names.

CHA has no command to copy a character.

Character settings

Field Values Function
Provider A provider The model service and the model.
Reasoning effort Provider default, None, Low, Medium, High, Extra high Replaces the reasoning effort of the provider.
Provider web search Provider default, Off, Automatic The web search function of the model service. See Two kinds of web search.
On-demand web search Workspace default, On, Off The web search and page reading that CHA does. Off also stops page reading for this character.
Style No style, or a style How the text of the character looks. See Styles.
Voice Application default, or a voice The voice for audio. See Voices.

Below Voice there is a text field for a voice test. The button Play preview shows only when voice output is configured.

If a saved provider, style or voice does not exist any more, the list shows its ID with (not available).

The profile and the instructions

The text that a model gets for a character has these parts, in this order:

  1. A protocol that CHA generates: the name and the nicknames of the character, the name of the persona, and the other members of the forum.
  2. The instructions that all characters share.
  3. The profile of the character.
  4. The instructions of the forum. See Forum instructions.
  5. The profile of the persona.

The shared instructions. Click Settings → Characters → Instructions. This text applies to all characters of the vault. Use it for rules on how characters write and behave. When you save it, the open sessions start again with the new text.

The profile. Click Edit character profile on the character screen.

See the result. The Members screen of a forum shows the complete text for each character. See See the system prompt.

The profile and the instructions can include other files and use variables. See Prompt files and the template language.

Files

On the character screen, click Character settings, then Files. The list shows the text files and the pictures of the character.

To add a file:

  1. Click New file.
  2. Type the Filename.
  3. Click Upload file and select a file, or click Write text and type the content.
  4. Click Add file.

Text files have the extension .md or .txt. If you type no extension, CHA adds .md. A text file has an effect only in these cases:

  • The profile or the instructions include it.
  • It is the nicknames file.
  • Its name has the form _<number>_<number>.md, for example _1_2.md. Such a file is a variant. For each session, CHA selects some of the variant files of the character and adds their text to the profile. The first number is a group. CHA uses a maximum of one file of each group in one session. Do not give this form of name to other files.

On the screen of a file you can rename it, edit it, replace its content from a file, and delete it.

The Settings screens do not show the file CHARACTER.md, which is the frame of the character text. To change it, use the configuration files. See Configuration files.

Nicknames

A nickname is a second name that users can call the character.

  1. Open Character settings → Files → New file.
  2. Type the file name nicknames.txt.
  3. Click Write text. Type one nickname on each line. A line that starts with # is a comment.
  4. Click Add file.

CHA uses nicknames in two places: the character knows its nicknames, and automatic recipient detection accepts them. The @ addressing in a message does not use nicknames.

Pictures

The picture panel of the chat shows the pictures of a character.

  1. Open Character settings → Files → New file.
  2. Click Upload file and select the picture.
  3. Click Add file.

The formats are PNG, JPEG, WebP and GIF. The limit is 8 MB for each picture. A character can have more than one picture. CHA stores the pictures in the vault database.

The Assistant

Assistant is a built-in character. It is the only member of the built-in forum Entrance, and it is the first member of each new forum.

  • You can change its Character settings and its pictures.
  • You cannot change its name or its text, and you cannot delete it.
  • It must always have a provider that exists. When no provider is selected for session naming, CHA uses the provider of the Assistant for that task.

Delete a character

CHA refuses to delete a character that is a member of a forum: This character is still used by one or more forums. Remove it from those forums first. The deletion removes the definition, the settings and the files of the character. The conversations stay.

A forum is a group of characters with one persona. Each forum has its own sessions and its own folder in Notes.

The forum Entrance

Entrance is built in. Its member is the Assistant, and its persona is Guest. You cannot change or delete it.

Create a forum

  1. Click Settings → Forums → New forum.
  2. Type a Name.
  3. Select a Persona.
  4. Click Create forum. The forum screen opens.

The new forum has the Assistant as its only member.

Rules for the name: a maximum of 200 characters; no space at the start or the end; different from all other forums. The names Entrance and ANNOTATIONS are reserved.

Open the forum screen

  1. Click Settings → Forums and then the forum, or click the forum in the sidebar. The Sessions screen of the forum shows.
  2. Click the row with the forum name and the member names.

The forum screen shows the files of the forum. It has the link Members.

Members

On the forum screen, click Members.

  • Persona selects the persona of the forum.
  • The list shows all characters of the vault. Select the check box of each character that is a member.
  • Click Save.

Rules:

  • A forum must have a minimum of one member.
  • Each member must have a provider. If not, the message is Select a configured persona and at least one configured character.
  • The members have no order that you can set.

See the system prompt

On the Members screen, click … on the row of a character. A dialog shows the text that the model gets for this character in this forum. It does not show the parts that CHA adds for one session, for example the list of the Library stores. Copy puts the text on the clipboard. The dialog also works for a character that is not a member, if the character has a provider.

Use this dialog to make sure that your profiles, instructions and variables give the result that you want.

Forum instructions

The file FORUM.md holds the instructions of the forum. All members get this text. A new forum has an empty FORUM.md.

  1. On the forum screen, click FORUM.md in the list of files.
  2. Click Edit forum file, write the text, and click Save.

You cannot delete FORUM.md. With New file you can add more Markdown files. A file has an effect only when FORUM.md includes it. See Prompt files and the template language.

Library

On the Members screen, click Library. See Select the Library of a forum.

Rename and delete a forum

When you rename a forum, CHA also renames its folder in Notes.

WARNING: When you delete a forum, CHA deletes all its sessions, its folder in Notes, and all notes in that folder. You cannot undo this.

Settings that have no screen

What a vault is

A vault is two files in the configuration directory:

To select the active vault, use the Vault list at the bottom of the sidebar. See the User Manual. CHA writes the selection into app.toml, and starts with that vault the next time.

Create a vault

  1. Click Settings → Vaults → New vault.
  2. Type the Display name.
  3. Select the Initial database:
    • New empty vault — the new vault gets a copy of the configuration of the active vault: characters, forums, providers, saved keys and settings. It gets no sessions and no notes.

CAUTION: With the two selections, the new vault gets the saved keys, the R2 credentials and the D1 credentials of its source. With D1 credentials, the new vault does not synchronize until you select it and click Save D1 credentials. Until you do this, or click Disconnect from D1, CHA refuses an R2 upload of the new vault after its first change. See D1 synchronization.

Rename a vault

Open Settings → Vaults, click the vault, and click its title.

CHA changes the name in the definition file and renames the directories of the vault in the mirror and modify directories. The name of the database file does not change.

CAUTION: Do not rename a vault that uses D1 synchronization. The vault name is part of the synchronization. See D1 synchronization.

If the vault has a copy in R2, upload it again after you rename it. Until then, Download fails, because the copy in R2 has the old name.

Protect a vault with a password

A protected vault has an encrypted database. CHA asks for the password each time it opens the vault.

To protect an existing vault:

  1. Click Settings → Vaults and click the vault.
  2. Select Protected vault.
  3. Type the Password.
  4. Click Protect vault.

WARNING: You cannot change the password, and you cannot remove it. If you lose the password, you lose the vault. CHA has no recovery function. Keep the password in a safe place before you click Protect vault.

What the password does and does not protect:

  • The database file is encrypted: configuration, saved keys, sessions, notes.
  • The definition file and app.toml are not encrypted.
  • CHA writes no session mirror for a protected vault.
  • The files that Export writes are not encrypted.
  • Files that CHA made before the protection stay on the disk as they are: the session mirror of the vault, an export in the modify directory, and a .bac file. Delete them yourself.

To get a vault with a different password, or with no password, create a new vault with Copy vault name and set the password that you want. The copy is a new vault with a new name.

  1. Click Settings → Vaults, click the active vault, and click Merge.
  2. Select the Source vault and click Merge.
  3. Confirm.

When the two vaults have the same item, the item of the source replaces the item of the active vault. This includes the saved keys and the R2 credentials. You cannot undo a merge. The D1 credentials of the active vault do not change.

If the source vault is protected, CHA asks for its password.

Delete a vault

  2. Click Settings → Vaults, click the vault, and click Delete vault.
  3. Confirm.

CHA deletes only the definition file. The database file and the directories of the vault stay on the disk. To remove the data, delete the database file yourself.

Because the database file stays, you cannot create a new vault with the same name until you move or delete that file.

<file>.sqlite3.toml The definition of the vault.
<file>.sqlite3.uploader The registration of the computer that uploads.

  2. Set the fields:

    Field Value
    R2 URL https://<account ID>.r2.cloudflarestorage.com/<bucket> — the S3 address with the bucket name as the only path part.
    Access key ID The access key ID of the token.
    Secret key The secret key of the token.

  3. Click Save R2 credentials.

The credentials belong to the active vault. CHA examines the address only when you use it.

To remove them, click Remove R2 credentials.

Upload a vault

  1. Click Settings → Vaults and click the active vault.
  2. Click Upload.
  3. If CHA asks, confirm. CHA asks when it has no record of an earlier transfer, when the copy in R2 is different from the last transfer of this computer, or when the copy in R2 does not exist any more.

Important points:

  • The upload does not include stored audio: not the audio of answers, and not the audio of notes. The local vault keeps its audio.
  • A protected vault stays encrypted in R2.
  • If the vault uses D1 synchronization and has changes that are not sent, CHA refuses the upload: Changes are not sent to D1 yet. Try again when D1 can be reached.

The uploading computer

The first upload of a vault registers your computer as the uploader of that vault. A different computer cannot upload the same vault. The message is:

Only the registered uploader machine can upload this vault to R2. To change it, delete '<file>.sqlite3.uploader' from the bucket.

To move the upload function to a different computer, delete that object in the bucket with the tools of Cloudflare. The next upload registers the new computer. On Windows, you must also do this after you install Windows again.

Downloads have no such limit.

Replace the active vault with the copy in R2

  1. Click Settings → Vaults and click the active vault.
  2. Click Download.
  3. Read the dialog Replace the local database? and click Download.

WARNING: The download replaces the complete local database: the configuration, all sessions and all notes. The changes that you made after the upload are lost. All stored audio of the vault is lost, because the copy in R2 has none.

  3. Click a row. CHA downloads the vault without a confirmation.
  4. Select the new vault in the Vault list of the sidebar.

CHA cannot download a protected vault with this command. Protected vaults show in the list, but the download fails. To move a protected vault, copy its files. See Move a vault to a different computer.

If a transfer fails

The screen shows a short message, for example Upload failed. or The request could not be completed. The reason is in the log. See The log. Frequent causes are a wrong address, a token without the necessary permissions, and no network connection.

20. D1 synchronization

In this chapter
  • How it works
  • What is synchronized
  • Rules
  • What you need in Cloudflare
  • Set up the first computer
  • Add a second computer
  • Stop the synchronization
  • Synchronization and R2 together
  • Problems

D1 synchronization sends the changes of a vault to the other computers that use the same vault. It uses one database in Cloudflare D1 as the transport.

How it works

  • Each computer has a name, the machine name.
  • For each vault and each computer, CHA makes one table in the D1 database. The name of the table is q/<vault name>/<machine name>.
  • When you change something, CHA puts a record into the tables of the other computers. Each computer reads its own table, applies the records, and deletes them.
  • CHA does this when it opens the vault, and then every 30 seconds. When it closes, it sends its changes one more time. There is no command to start it.

CHA applies the records in the order in which they come. It does not compare versions. If you change the same item on two computers at the same time, the change that comes last replaces the other.

Thus a change is on the other computers after a maximum of approximately one minute, if the two computers are in operation and connected.

What is synchronized

Synchronized Not synchronized
Notes and folders Stored audio of answers and notes
Configuration: personas, characters, forums, providers, styles, voices, settings, pictures Events
Saved API keys and R2 credentials D1 credentials
Sessions that have a name and whose first message is complete (answered, failed or stopped) The machine name, app.toml, the vault password
The ChatGPT connection

When a note changes through synchronization, CHA deletes the stored audio of that note.

Rules

  • Each computer must have a different machine name. Capital letters do not make a name different.
  • The vault must have the same name on all computers.
  • Only the main process synchronizes.
  • D1 moves changes. It does not move a complete vault. A new computer first gets the vault through R2.

What you need in Cloudflare

  • The account ID.
  • One D1 database, and its database ID. The database can be empty. CHA makes its tables.
  • An API token that permits CHA to read and to change that D1 database.

Set up the first computer

  1. Close CHA.

  2. Open app.toml in the configuration directory and add this line above the line [logging]:

    machine = "<machine name>"

    The name cannot be empty and cannot contain /.

  3. Start CHA and select the vault.

  4. Click Settings → API Keys → D1 sync.

  5. Type the Account ID, the Database ID and the API token.

  6. Click Save D1 credentials.

CHA makes the table of this computer and starts the synchronization. If the machine name is missing, the message is This machine has no name. Add machine to app.toml, then save again.

Add a second computer

Do not change the vault on a different computer during this procedure. Changes that are made between step 1 and step 6 do not come to the new computer.

  1. On the first computer, upload the vault to R2. See Upload a vault.
  2. On the second computer, set the machine name in app.toml to a name that no other computer uses, and start CHA.
  3. Save the R2 credentials in the active vault. See Save the R2 credentials.
  4. Get the vault with Download vault, and select it in the Vault list. The vault contains the D1 credentials. For a protected vault, copy the files in place of this step. See Move a vault to a different computer.
  5. Click Settings → API Keys → D1 sync. The fields show the saved values.
  6. Click Save D1 credentials. You can keep API token empty. This step makes the table of the second computer and starts the synchronization.

Until step 6, the second computer does not synchronize, and no screen tells you so. The log contains D1 sync stopped: download the vault from R2, or save the D1 credentials again.

Stop the synchronization

  1. Click Settings → API Keys → D1 sync.
  2. Click Disconnect from D1 and confirm.

CHA removes the D1 credentials from this vault on this computer, deletes the changes that are not sent, and deletes the table of this computer in D1.

Disconnect each computer that stops using a vault. If you do not, its table stays in D1 and continues to collect records.

Synchronization and R2 together

  • An R2 upload is possible only when all changes are sent to D1.
  • After Download on the active vault, CHA makes the table of this computer again, if it is missing, and synchronizes.
  • Import and Merge keep the D1 credentials of the target vault. A new vault gets the D1 credentials of its source. See Create a vault.

Problems

The synchronization writes its problems only into the log. No screen shows them. See The log. Search the log for D1 and for Skipped.

Log message Cause and action
D1 sync stopped: download the vault from R2, or save the D1 credentials again. The table of this computer does not exist in D1. Click Save D1 credentials again, or use Download on the vault.
D1 rejected the API token. The token is wrong or has no permission. Save a correct token.
D1 request was rate limited (HTTP 429). CHA tries again in the next cycle.
D1 daily row read limit exceeded. / D1 daily row write limit exceeded. A limit of the Cloudflare account. CHA tries again later.
D1 sync dropped the largest queue table to free space. The D1 database was full. This computer deleted the table with the most waiting records. That table can belong to a different computer of each vault in this D1 database. The computer that lost its table did not get those changes. Its log shows D1 sync stopped. To give it a complete copy: upload the vault to R2 from the uploading computer, then use Download on the computer that lost its table.
Skipped incoming sync record… CHA could not apply one record and ignored it.

21. Configuration files: export, edit, import

In this chapter
  • Principles
  • The directory
  • Change the configuration with files
  • What Import reads
  • What Import keeps
  • Errors and warnings
  • What an export does not contain

The Settings screens are the usual way to change the configuration. Some settings have no screen. For these, and for large changes, CHA can write the complete configuration of a vault to files and read it back.

Principles

  • CHA keeps the configuration in the vault database. It does not read the files while it operates.
  • Export writes the configuration to a directory.
  • Import replaces the configuration with the content of that directory.
  • A change in the files has no effect until you import. A change on the Settings screens does not change the files. Thus always export immediately before you edit.

The directory

The key modify in app.toml sets a base directory. Each vault uses the directory <modify>/<vault name>. With the first app.toml, this is the directory modify/<vault name> in the configuration directory.

If app.toml has no modify key, the rows Import and Export are disabled and show Modify directory is not configured.

Change the configuration with files

  1. Click Settings → Vaults and click the active vault.
  2. Click Export. The result shows as Exported with the number of files.
  3. Edit the files in <modify>/<vault name>. See Configuration file layout and keys.
  4. Click Import, and confirm in the dialog Import workspace configuration?
  5. If the screen shows an error, correct the file that the error names, and click Import again. The vault does not change when an import fails.

You do not have to restart CHA. The open sessions get the new configuration.

WARNING: Export writes all saved keys to files as plain text: the API keys, the R2 credentials and the D1 credentials. The files are in system/keys/. This is also true for a protected vault. Delete the export directory when you do not need it, and do not put it into a backup or a shared directory.

WARNING: Export first deletes the complete directory <modify>/<vault name>, without a confirmation. Changes in that directory that you did not import are lost.

WARNING: Import replaces the complete configuration. Each item that is not in the files is removed from the vault: characters, forums, providers, styles, voices and saved keys. When a forum is not in the files, CHA also deletes the sessions of that forum and its folder in Notes with all its notes.

What Import reads

  • Files with the extension .toml or .md.
  • Files with the extension .txt, but only below characters/.
  • Pictures, but only in the directory of a character and in system/assistant/.

Import ignores all other files. It stops with an error when one of the files that it reads is a symbolic link.

Import removes a forum member whose character is not in the files. If a forum then has no member, Import removes the forum, as the warning above describes. It gives no message for this.

What Import keeps

  • The sessions and the notes, with the exception in the warning above.
  • The D1 credentials of the vault. Import ignores D1 credentials in the files.

Errors and warnings

  • An error in a file stops the import, and the screen shows the text. The text names the file and, for a syntax error, the line.
  • Some problems are only warnings. The import continues, and the warning goes to the log: an unknown key, an obsolete key, a picture in a wrong place.
  • If the screen shows only Import failed. or a general message, the reason is in the log. An example is a missing directory.

What an export does not contain

Sessions, notes, stored audio, app.toml, the vault definition, and the ChatGPT connection.

22. The Assistant as a configuration tool

In the session Welcome, the built-in character Assistant can examine and change the configuration when you ask it to. You type what you want in normal words. It has this function only in the Welcome session. As a member of a different forum, the Assistant is a normal character.

What it needs

The Assistant needs a provider that works, and a model that supports function calls. In a new vault, its provider is chatgpt. Thus you must first connect a ChatGPT account, or select a different provider for it. See Minimum setup.

To change its provider: Settings → Characters → Assistant → Character settings. The Assistant cannot change its own settings.

What it can do

Area Functions
Examine The version, the vaults, the providers, characters, personas, forums, styles, voices and service settings. Which keys exist. The list of sessions and notes.
Change the configuration Create and change characters, personas, forums and their members, providers, styles, voices. Change the session, notes, search and voice settings.
Diagnose Read the log: the current file and cha.1.log. Read the Events and the state of background tasks. Change the log level until the next start.
Application files Read and change app.toml and the vault definition files. Such a change needs a restart of CHA.
ChatGPT Start the connection of a ChatGPT account and complete it.
Web Search the web and read pages, if the Search API is configured for it.

What it cannot do

  • Delete an item, or remove a member from a forum.
  • Read or write the value of a key. It sees only which keys exist. It cannot save a new key.
  • Make a key go to an address that this key does not already use. Thus it cannot change the address of a provider or a service that has a key, and it cannot select a key for a provider or a service at a new address.
  • Change its own settings, or the provider that it uses.
  • Read the text of sessions or notes.
  • Change pictures.
  • Create the database of a vault. Select, protect or delete a vault. Import, export, upload or download.
  • Start, stop or repeat a background task.
  • Run commands on the computer.

Rules of operation

  • A change applies immediately. CHA has no confirmation dialog for it. The Assistant is instructed to change something only when you ask for a change, and only to examine when you ask a question.
  • After a change, the conversation shows Configuration was saved. with the list of changed files, and tells you if an undo is available.
  • You can ask the Assistant to undo its last change. This is possible only when the change did not create a new item. An undo is not available after a restart of CHA, after a later change of the configuration, or for app.toml and the vault definition files.
  • After a change of app.toml or a vault definition file, the conversation shows Host configuration was saved. Restart is required.
  • The other open sessions start again with the new configuration.
  • CHA does not keep the Welcome conversation after you close the application. The changes stay.
  • The Assistant sends the configuration texts and the log lines that it reads to the model service of its provider. CHA never sends the value of a key. In log lines and Events, CHA replaces key values and private paths before it sends them. It sends the configuration files as they are, app.toml and the vault definition files with their paths included.

Examples of requests

  • “Why does the character Anna not answer?”
  • “Create a character with the name Boris for the forum Workshop. Use the same provider as Anna.”
  • “Change the model of the provider Main to <model name>.”
  • “Read the Events and tell me why the audio of my note failed.”
  • “Set the log level to debug.” Then repeat the problem and ask: “What does the log show?”
  • “Undo the last change.”

The Assistant in ChaWeb

In ChaWeb, the Assistant has the same functions. It works on the vault, the configuration directory and the log of the server. ChaWeb has no Settings screens, so there the Assistant is the tool to change the configuration and to read the Events.

Its knowledge

The knowledge of the Assistant about CHA is part of the application. You cannot change it.

  • The reason when a character cannot search the web or the Library, for example a missing key.

24. Backup and restore

In this chapter
  • What to copy
  • Make a backup
  • Restore a vault
  • Restore from a .bac file
  • Move a vault to a different computer
  • R2 as a second copy
  • The session mirror

CHA has no backup command. A backup is a copy of files.

What to copy

For one vault:

  • The definition file of the vault (a .toml file in the configuration directory).
  • The database file that the definition names in data.
  • If they exist, the files with the same name as the database and the endings -wal and -shm.

For the complete installation, copy the complete configuration directory. It also contains app.toml, the ChatGPT connection (openai-auth.json), and the state of the View menu (view.json).

Make a backup

  1. Close all CHA processes that use the vault: each CHA window, and ChaWeb if it uses the same files.
  2. Copy the files to the backup location.

Do not copy the database while CHA is in operation. The copy can be damaged.

For a protected vault, the backup is encrypted. You need the password to use it.

CAUTION: The backup of a vault without a password contains all saved keys as plain text. The complete configuration directory also contains the ChatGPT connection. Keep backups in a safe location.

Restore a vault

  1. Close all CHA processes.
  2. If you replace a database, delete the files with the same name and the endings -wal and -shm in the configuration directory.
  3. Copy the definition file and the database file back into the configuration directory. If the backup contains -wal and -shm files, copy them too.
  4. Make sure that the key data in the definition file gives the correct path of the database. For a vault that you created or downloaded, CHA writes a full path there. If the directory is different now, change the value. A file name without a directory is sufficient when the database is in the configuration directory.
  5. Start CHA.

If the vault uses D1 synchronization, the restored vault does not get the changes that the other computers sent after the backup. Changes that waited for D1 at the time of the backup are sent again.

Restore from a .bac file

When Download replaces a vault, CHA keeps the replaced files: <database file>.bac and <definition file>.bac. CHA has no command to restore them. To go back to the replaced vault:

  1. Close all CHA processes.
  2. In the configuration directory, move the current database file and definition file to a different location. Also move the files with the endings -wal and -shm, if they exist.
  3. Remove the ending .bac from the two .bac files.
  4. Start CHA.

Move a vault to a different computer

For a vault without a password, use R2. See Get a vault that is not on this computer.

For a protected vault, or without R2:

  1. Make a backup of the vault, as above.
  2. On the other computer, close CHA. Make sure that its configuration directory has no vault with the same name, no definition file with the same file name, and no database file with the same file name. Each installation has default.toml and default.sqlite3, and each installation starts its file names at vault-1.toml. If necessary, give the definition file that you copy a different file name. If two vaults have the same name or the same database file name, CHA does not start.
  3. Restore the vault, as above. Set data to the file name of the database.
  4. Start CHA and select the vault.

If the vault uses D1 synchronization:

  • Before the copy, upload the vault to R2 on the source computer. The upload is possible only when no changes wait for D1. Then close CHA and make the copy. A copy with changes that are not sent sends them a second time.
  • The machine name is in app.toml, not in the vault. If you copy the complete configuration directory, change machine on the new computer to a name that no other computer uses.
  • On the new computer, click Save D1 credentials. See Add a second computer.

R2 as a second copy

An R2 upload is a copy outside the computer. It does not contain stored audio. It is one copy: each upload replaces the copy before it.

The session mirror

With the key mirror in app.toml, CHA writes each session as a Markdown file into <mirror>/<vault name>/<forum name>/. These files are for reading with other programs. CHA never reads them back. They are not a backup that you can restore.

CHA writes no mirror for a protected vault and none for the Welcome session.

  • Test the installation
  • Connect a ChatGPT account on the server

  • What does not work on the server

ChaWeb is the browser client of CHA. It needs a server with Linux.

Structure

browser  →  nginx (HTTPS, one port for each user)  →  socket  →  cha-daemon  →  vault
  • cha-daemon is the CHA program for the server. It has no window.
  • For each user, one cha-daemon process operates on one configuration directory with one vault. The key vault in app.toml selects the vault.
  • systemd starts the process for a user when the first request comes (socket activation). The process then stays in operation.
  • nginx gives the ChaWeb files to the browser, does the HTTPS encryption, and sends the requests to the socket of the user.
  • All processes operate with one Linux account: the account that installs the package.

WARNING: ChaWeb has no login. Each person who can connect to the port of a user can read and change all data of that user, and can use the model services at the cost of the saved keys. Make each ChaWeb port available only on a private network that you trust. If you add an access control in nginx, for example a password or client certificates, this is not a function of CHA, and you must make sure yourself that ChaWeb operates correctly with it.

Requirements

  • A Linux server with systemd and nginx.
  • A regular user account with sudo. Do not do the installation as root.
  • The package cha-linux-<version>.tar.gz. See Appendix A. The package must come from a build computer with a compatible Linux version.
  • For each user: a free port, and a TLS certificate for the host name of the server.

ChaWeb must be at the top of an address: https://<host name>:<port>/. You cannot put it below a path such as /chaweb/.

Install the package

  1. Copy the package to the server and extract it:

    tar -xzf cha-linux-<version>.tar.gz
cd cha-linux-<version>

  2. Set the two directories and start the installer:

    export CHA_DEPLOY_PATH=<program directory>
export CHA_DATA_PATH=<data directory>
./install.sh
    • The two paths must be full paths. They can contain only letters, digits and the characters _ . / + -.
    • CHA_DATA_PATH must not be in $CHA_DEPLOY_PATH/chaweb.
    • Use a program directory that contains only CHA. The installer makes your account the owner of all files in it.
    • The installer uses sudo for the system changes.

The installer does these tasks:

  • It copies cha-daemon, add_user.sh, the nginx example and the example vault to CHA_DEPLOY_PATH.
  • It replaces $CHA_DEPLOY_PATH/chaweb with the ChaWeb files.
  • It writes the systemd units /etc/systemd/system/cha@.service and /etc/systemd/system/cha@.socket, if they do not exist.
  • It makes a test that nginx can read the ChaWeb files, and shows a warning if it cannot.

The installer starts no service and does not change the nginx configuration.

The socket group. The socket of each user is /run/cha/<user>.sock with the group www-data. If nginx on your server uses a different user, change SocketGroup in /etc/systemd/system/cha@.socket to a group of that user. Then do sudo systemctl daemon-reload. Do this before you add the first user. The procedure to add a user fails if the group does not exist.

Access to the ChaWeb files. nginx must be able to read $CHA_DEPLOY_PATH/chaweb and to go through each directory above it. If the installer shows a warning, use a program directory that is not in a private home directory. Do not make the directories in CHA_DATA_PATH readable for nginx.

Prepare the vault of a user

Each user has the configuration directory $CHA_DATA_PATH/<user>/config. <user> is a name that you select for ChaWeb. It is not a Linux account. It starts with a small letter and contains only small letters, digits, _ and -.

You have two possibilities.

Use the example vault. If the directory does not exist, the next procedure creates it with the example vault. This vault has the name Personal, one forum with three characters, and the provider chatgpt for a ChatGPT subscription. It has no API keys.

Use a vault that you made on the desktop. Configure the vault in the desktop application first: providers, keys, characters, forums and voices. Then, before you add the user:

  1. Close CHA on the desktop.
  2. Copy the files to the server into $CHA_DATA_PATH/<user>/config: app.toml, the definition file of the vault, and the database file. See Backup and restore.
  3. In app.toml, set vault to the name of the vault. Keep the section [logging] with file and level. The process does not start without it. Remove the keys mirror and modify, or set them to directories of the server. With mirror, the server writes readable copies of the sessions of a vault without a password.
  4. In the definition file, set data to the file name of the database.
  5. If the vault uses D1 synchronization, set machine in app.toml to a name that no other computer uses. Read the rules in Move a vault to a different computer.

The server does not create a first configuration. The directory must contain app.toml, a vault definition, and the database before the process starts. Each other .toml file in the directory must be a correct vault definition.

Add a user

  1. Set the two variables again, and run:

    export CHA_DEPLOY_PATH=<program directory>
export CHA_DATA_PATH=<data directory>
"$CHA_DEPLOY_PATH/add_user.sh" <user>

    The script creates the configuration directory with the example vault, if the directory does not exist. It sets the permissions, and it enables the socket cha@<user>.socket.

  2. Add a server block for the user to nginx. See the next section.

Configure nginx

The file $CHA_DEPLOY_PATH/nginx-chaweb.conf.example is one server block.

  1. Copy it into the http context of nginx, for example as a file in /etc/nginx/conf.d/.

  2. Make one server block for each user, and change these lines:

    Line Change to
    listen The private address and the port of this user, with ssl. Each user has a different port.
    server_name The host name that the browsers use.
    ssl_certificate, ssl_certificate_key Add these two lines with the paths of your certificate and key. The example does not contain them.
    root <program directory>/chaweb, the same for all users.
    scgi_pass unix:/run/cha/<user>.sock

  3. Do not change the other lines of the block location /api/cha/v1/: the buffer settings, the limit of 256 KiB for a request, and the cache headers.

  4. Test and load the configuration:

    sudo nginx -t
sudo systemctl reload nginx

The http context must include mime.types, and nginx must have its standard file scgi_params.

The browser of the user must find the host name, reach the port, and trust the certificate. The microphone of ChaWeb works only with HTTPS.

Test the installation

systemctl status cha@<user>.socket
curl -sI https://<host name>:<port>/
curl -s https://<host name>:<port>/api/cha/v1/bootstrap
  • The socket must be active.
  • The first request must give the status 200 and the content type text/html.
  • The second request must give JSON text with the forums of this user. This request starts the process of the user.

Then open https://<host name>:<port>/ in the browser and send a message. With the example vault, connect a ChatGPT account first. See the next section.

Connect a ChatGPT account on the server

Use this procedure when a provider of the vault uses the ChatGPT subscription. The example vault does.

  1. On the server, with the account that installed the package, run:

    "$CHA_DEPLOY_PATH/cha-daemon" --config "$CHA_DATA_PATH/<user>/config" --openai-login

  2. The command shows an address and a code, and then Waiting for approval...

  3. Open the address in a web browser on any device, sign in, type the code, and approve.

  4. The command shows Connected to ChatGPT. and stops.

If an account is already connected, the command shows only Connected to ChatGPT.

The command writes openai-auth.json into the configuration directory of the user. Each user has a separate connection. You do not have to start the process of the user again. It reads the connection with the next message.

When the Assistant of the vault already works, you can also ask it in ChaWeb to connect the account. It shows the address and the code. Approve, and then answer “Done”.

The password of a protected vault

The server cannot ask for a password. For a protected vault, put the password into the file password in the configuration directory of the user.

  1. Create $CHA_DATA_PATH/<user>/config/password with the password as its only line.

  2. Set its permissions:

    chmod 600 "$CHA_DATA_PATH/<user>/config/password"

The file must be a regular file with the permissions 600 exactly. The account that installed the package must be its owner, because the process must be able to read it. It cannot be a symbolic link, and it cannot be empty. Its maximum size is 4,096 bytes. If not, the process does not start.

CAUTION: The password is in this file as plain text. Each person who can read the files of the service account can open the vault.

Change the configuration of a server vault

ChaWeb has no Settings screens. You have these possibilities:

  • The Assistant. In ChaWeb, open the conversation with the Assistant and ask it. ChaWeb shows the built-in forum with the name Welcome. See The Assistant as a configuration tool. The Assistant cannot save API keys. After the Assistant changes app.toml or a vault definition file, start the process again with sudo systemctl restart cha@<user>.service.
  • D1 synchronization. If the server vault and a desktop vault synchronize, change the configuration on the desktop. The change, saved keys included, comes to the server.
  • A new copy. Stop the process, replace the vault files with a new copy from the desktop, and start again.

To stop the process of a user for work on its files, stop the socket too. If not, the next request starts the process again:

sudo systemctl stop cha@<user>.socket cha@<user>.service
# change the files, then:
sudo systemctl start cha@<user>.socket

What does not work on the server

  • The generation of note audio.
  • Vault commands: create, select, R2 transfer, import and export.

D1 synchronization works on the server. Each time the process starts, it makes the D1 table of the server if that table is missing.

Operate the service

Task Command
See the state systemctl status cha@<user>.socket cha@<user>.service
Start the process again sudo systemctl restart cha@<user>.service
Stop sudo systemctl stop cha@<user>.socket cha@<user>.service

The log path in the table is the path of the example vault. The key [logging] file in app.toml sets it.

Errors that occur before the log starts, for example an error in app.toml or a missing database file, are only in the journal of systemd. An error of the password file is in the journal and in the log.

Problems

Symptom Examine
nginx does not start or load sudo nginx -t, and the error log of nginx.
Status 403 or 404 for / or /assets/ The root line, and the access of nginx to the ChaWeb files.
Status 502 for the API The socket group and the group of nginx. Then the state of the two units and the journal.

Update

Always install cha-daemon and the ChaWeb files from the same package.

  1. Extract the new package and run install.sh with the same two paths.

  2. Start the processes again:

    sudo systemctl try-restart 'cha@*.service'

  3. Tell the users to load the page again in the browser.

The installer replaces the program, the scripts, the example vault and the ChaWeb files. It keeps the systemd units, the nginx configuration and the vaults of the users. Because it keeps the units, a change of the two paths has no effect on them. If you change a path, correct ExecStart in /etc/systemd/system/cha@.service yourself. Compare the new nginx-chaweb.conf.example with your server blocks, and copy the changes that you need.

Remove

The package has no command to remove the installation. Do the installation steps in the opposite order:

  1. For each user: sudo systemctl disable --now cha@<user>.socket and sudo systemctl stop cha@<user>.service.
  2. Remove the server blocks from nginx and load its configuration again.
  3. Delete /etc/systemd/system/cha@.service and /etc/systemd/system/cha@.socket. Then do sudo systemctl daemon-reload.
  4. Delete the program directory.
  5. Delete the data directory, if you do not need the vaults.

Rules:

  • mirror and modify are base directories. CHA adds the vault name.
  • The directory <modify>/<vault name> of a vault cannot be the configuration directory or contain it, and it cannot contain a vault database.
  • A missing necessary key, a value of the wrong type, or a syntax error stops the start. The key machine is the exception: CHA ignores an incorrect value and writes a warning to the log.
  • An unknown key does not stop the start. CHA ignores it and writes a warning to the log.

General rules for keys

30. Prompt files and the template language

In this chapter
  • The files
  • Include a file
  • Variables
  • Other rules
  • Example

A prompt file is a Markdown file whose text goes to the model. This chapter describes how CHA puts these files together. It does not tell you how to write good texts for characters.

The files

File Function Where you edit it
characters/character-voice.md Instructions for all characters. Settings → Characters → Instructions
characters/…/CHARACTER.md The frame of the text of one character. Configuration files only
characters/…/PROFILE.md The profile of one character. The character screen
Other .md and .txt files of a character Text that a different file includes. Character settings → Files
forums/…/FORUM.md The instructions of one forum. The forum screen
forums/…/members/…/CHARACTER.md Text for one member in one forum. Configuration files only
personas/…/PERSONA.md The profile of one persona. The persona screen

A character that you create on the screen gets this CHARACTER.md:

$$(../character-voice.md)

<character_profile>
$$(PROFILE.md)
</character_profile>

Thus the text of the character is the shared instructions, then its profile. If you write a different CHARACTER.md that does not include PROFILE.md, the character screen shows This character has no PROFILE.md file. when that file does not exist.

If you put the directory of a character into a subdirectory, the first line does not find the shared file. Use $${CHARACTER_VOICE} in place of it.

A file of a character with a name of the form _<number>_<number>.md is a variant file. See Files. CHA adds the text of the selected variant files to the profile as it is. Includes and variables do not work in these files.

Include a file

$$(<relative path>)

CHA replaces this with the content of the file. The path starts at the directory of the file that contains the line.

  • A character file can include files below characters/.
  • A forum file can include files in the directory of its forum.
  • You cannot include a picture.
  • An included file can include more files, to a depth of 16. One text can have a maximum of 256 includes.
  • The complete text has a maximum of 1 MiB.

Two fixed names include the shared files from each location:

Text Includes Available in
$${CHARACTER_VOICE} characters/character-voice.md Character and forum files
$${FORUM_DEFINITION} forums/forum-definition.md FORUM.md and the files that it includes

Variables

$${<name>}

CHA replaces this with the value of the variable. A name can contain letters, digits, _, - and .. An unknown variable is an error.

Variables that CHA supplies:

Variable Value Available in
character.id, character.display_name The character that gets the text. Character and forum files
forum.id, forum.display_name The forum of the session. Character and forum files
persona.id, persona.display_name The persona. PERSONA.md

You define your own variables in [prompt] tables. The values can be texts, numbers, and true or false. For a character in a forum, CHA reads the tables in this order. A later table replaces the values of an earlier table:

  1. [prompt] in the character.toml of the character.
  2. [prompt] in members/character_defaults.toml of the forum.
  3. [prompt] in members/<character-id>/character.toml of the forum.

For a persona, CHA reads [prompt] in persona.toml.

Because CHA makes the text of FORUM.md for each member separately, FORUM.md can use the variables of the member. Each variable in FORUM.md must have a value for each member of the forum, the Assistant included. If not, the error unknown variable stops the save or the import.

Rules for [prompt] tables:

  • They have no screen. Use the configuration files.
  • Put them only in the files that this section names.
  • A name with a period must be in quotation marks: "a.b" = "<value>".
  • A list or a table as a value is an error.

Other rules

  • To write the two characters $$ as text before ( or {, type $$$.
  • An include or a variable must be complete on one line.
  • The language has no conditions and no loops.
  • An error message gives the file, the line and the column.

Example

forums/<forum-id>/members/character_defaults.toml:

[prompt]
topic = "<topic of this forum>"

forums/<forum-id>/FORUM.md:

In this forum, $${character.display_name} talks only about $${topic}.

To see the result, use See the system prompt.
