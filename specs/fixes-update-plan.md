## U6. Session mirror and configuration refresh

1. **Set the destination root before receiving.** In `switch_vault_locked`, after the destination database and session repository have reopened and their maintenance guards have been released, call the existing best-effort `rebuild_mirror(session_mirror_root(selected))` before `end_maintenance_locked`. This also clears the old root when the destination is protected or has mirroring disabled. Remove the later duplicate rebuild. Apply the same ordering to a successful R2 replacement or an active vault edit that changes protection or mirror location. A failed rebuild must leave mirroring disabled. [Switch](../src/app/vault_operations.cpp#L1008) · [Maintenance callback order](../src/app/vault_operations.cpp#L568) · [First receive](../src/app/application.cpp#L439)
2. **Keep the forum mappings current.** Reuse the directory naming and collision rules in `SessionMirror`. Under its mutex, retain mappings for surviving forums, forget removed forum IDs and their cached session paths, and allocate paths for added forums from their current display names. For a runtime addition, avoid overwriting archived files when selecting the directory. Keep archived files on disk. Use the same reconciliation after a successful Settings create/delete, Welcome apply/undo, D1 configuration commit, and configuration import. Run it against the committed destination workspace before a write for an added or reused ID. For D1, apply the forum change before handing a subsequent changed chat to the mirror, including during the initial pass. Keep mirror errors best-effort. [Mirror allocation and updates](../src/session/session_mirror.cpp#L115) · [Configuration commit](../src/workspace/workspace_config_store.cpp#L1623) · [Import](../src/app/vault_operations.cpp#L1354)
3. **Refresh a window recovering a live session.** In `beginRecovery`, refresh bootstrap once when the current `reopen` settles, including a non-retryable failure for a deleted target. Keep the existing cancellation and generation checks so a stale attempt cannot update a different context. [Recovery](../webapp/src/useLiveSession.ts#L376)

**Acceptance tests**

- In `unit_vault_maintenance.cpp` and the existing D1 app fixture, switch from a mirrored vault A to B with incoming configuration and chat records on B's **first** receive pass. Check the transcript appears only under B and A's files and contents are unchanged. Repeat with a protected B and verify no B transcript appears under either root. Use an overlapping forum ID to exercise the existing failure. [D1 fixture](../tests/app/unit_d1_sync.cpp#L533)
- In the mirror and application tests, exercise a runtime addition, configuration import, and delete/recreate with a reused `forum_1` ID and a different display name. Verify the new chat is written in the correct directory, that surviving forum paths stay stable, and that an archived transcript is preserved. Extend the D1 forum-then-chat test with an assertion on the actual Markdown file. [Mirror tests](../tests/session/unit_session_mirror.cpp) · [Import fixture](../tests/app/unit_vault_maintenance.cpp#L704)
- In `useLiveSession.test.ts`, verify that the current recovery refreshes bootstrap once on a successful reopen or a deleted target. A superseded attempt must not trigger a refresh. [Recovery tests](../webapp/src/useLiveSession.test.ts)

## U4. Bind background provider requests to the admitted vault

1. **Flex Test.** Keep the existing synchronous admission, provider lookup, key binding and eligibility checks. [Flex Test](../src/notes/notes_operations.cpp#L445)
2. **Settings Test.** Keep the initial provider lookup under admission. Prepare the candidate and client under the lock and run the actual request in the background. [Application entry point](../src/app/application.cpp#L1328) · [Test preparation and error handling](../src/app/settings_operations.cpp#L437)

If the original key is gone, fail the formatting request. Keep ordinary short-page imports independent of formatter configuration. Release the lock before reporting progress or performing inference. Reuse `collect_note_prompt` and remove `run_note_prompt` if it has no remaining caller. [Snapshot](../src/notes/notes_operations.cpp#L1009) · [Formatting admission](../src/notes/notes_operations.cpp#L1041) · [Client construction](../src/providers/provider_client.cpp#L499)
